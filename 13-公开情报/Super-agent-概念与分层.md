# Super-agent：概念、分层与三条不变量（公开版）

> 口径：只讲**公开概念、抽象分层与不变量**；不写实现、schema、脚本、阈值、客户数据。
> 概念来源：DeepSeek 公开的 Super-agent 架构讨论 + 社区公开文章；本页是**我们的理解**，不是官方规范。
> 核对日期：2026-11-01

## 一、七组概念（术语表）

| 概念 | 一句话 | 界面上对应什么 |
|---|---|---|
| **Router / Worker** | 路由器只做分派，工人只做一类活；路由不干活，工人不做决策 | 命令台派单 ↔ 各场景接单 |
| **Trigger / Thread** | 触发是「什么时候开始」，线程是「这一单的上下文」；两者分开记 | 定时/事件触发 ↔ 一次派单的会话 |
| **Policy / Mandate** | 策略是规则，授权是这次允许做到哪；授权不是永久的 | 权限分档 ↔ 单次任务的边界 |
| **Ticket / Assignment** | 工单是事实，指派是关系；一张单只能有一个当前 owner | 待办行 ↔ 归属字段 |
| **Subscription / Outbox** | 订阅是「谁关心」，发件箱是「发出去的东西」；先落发件箱再投递 | 通知看板 ↔ 台账 |
| **Inline & Spill** | 小结果直接回，大结果溢出到文件；溢出要留指针 | 直接回复 ↔ spill 文件 |
| **Watchdog** | 看门狗只负责「没动静就报」，不负责替人做决定 | 心跳/巡检 ↔ 告警 |

## 二、抽象拓扑：四层

```
决策层   —— 谁来做、做什么、什么时候做（路由 / 授权 / 优先级）
   ↓
执行层   —— 真的动手（工具 / 桌面 / 浏览器 / 文件）
   ↓
验收层   —— 做完读回、对证据、判通过与否（证据 > 声明）
   ↓
档案层   —— 一单一档：过程、证据、结论、可回滚点
```

四层之间是**单向依赖**：执行层不替决策层做判断，验收层不替执行层补动作，档案层不改前四层的结论（只记录）。

## 三、三条不变量

1. **一单一 owner**：同一件事在同一时刻只有一个负责人；换人要显式交接，不能"两个人都以为对方在做"。
2. **证据 > 声明**：说"做完了"不算，必须给可复核的证据（读回、日志、文件、URL）。
3. **人只批「解释 / 承诺 / 报价 / 新范围」类，口令类免批**：需要人点头的是"怎么解释、承诺什么、报多少、范围变没变"；口令/机械动作不逐条找人确认。

> 这三条比任何工具都重要：工具可以换，不变量不能丢。
