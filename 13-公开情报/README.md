## 口径（为什么这么写）

1. **事实与判断分开**：官方说什么就引原文链接；我们的判断单独一段，标「我们的判断」。
2. **只讲分层与不变量，不讲实现**：能说明「为什么这样设计」，不提供「照抄就能跑」的脚本。
3. **版本与日期必须可追溯**：每条事实带来源链接与日期；拿不准标「未证实」。
4. **对标不等于复刻**：商业软件的代码/界面/文案一律不复制，只提炼机制。

**三句话总结**：① 官方在变快，但你的产出取决于自己的机制；② 执行层先做"能读回的控件操作"，别一上来上视觉；③ 体验差距 = 四个机制，不是模型分数。

> 不适合谁看：想找"一键安装包"的人（这里全是判断与方法，没有安装包）。

## 更新方式

- 每次官方发版、或我们做完一轮公开调研，追加一篇或更新对应文档；
- 文末统一写「本页核对日期」，防止读者把旧结论当现状。
