## 一、事实（官方 Change Log）

来源：DeepSeek API Docs · Change Log <https://api-docs.deepseek.com/updates/>

### 2026-10-17
1. **开放自研搜索 API**：官方称其网页与 API 搜索由自研搜索引擎提供，日处理数亿次请求；索引千亿级网页，多语种，实时返回；对 SEO 垃圾、GEO 操纵、低质 AIGC 有过滤。
2. **DeepSeek-V4.1-Flash-1017 上线**：API 调用方式与价格不变，模型名仍用 `deepseek-flash`；官方称相比上一版在多榜单提升，并**降低任务耗时与输出长度**。
3. **官方要求的最低 Harness 版本**：建议升级到 **0.2.1-rc.1 或更高** 以配合新模型（原文：optimized for DeepSeek Harness 等平台）。

### 2026-09-10
- **DeepSeek-V4.1-Flash 发布**：新架构家族中最小的一档，原生多模态；API 降价；旧名 `deepseek-v4-flash` 暂时路由到新模型。

### 2026-08-13
- **DeepSeek-V4-Pro GA**：原生支持 **OpenAI Responses API**（适配 Codex）；思考强度支持 **low / high / max** 三档；开始峰谷定价。

## 三、我们的判断（不是官方说法）

1. **搜索 API 可以替换我们一部分「网页桥」**：过去用第三方网页版 AI 做检索/总结，现在官方有原生 search/fetch，链路更短；但要注意配额与计费方式。
2. **`deepseek-flash` 是滚动别名**：升级不换模型名，这对我们有利——不用改配置就能吃到新模型；但**回滚要靠版本记录**，所以我们自己维护「模型/引擎版本快照」。
3. **思考三档 = 任务分级**：简单检索用 low，日常 Agent 用 high，复杂改造用 max；这比"一律开最大"省成本。
4. **Harness 版本要跟**：官方点名了最低版本；我们本地有本地补丁，升级流程必须「先 stash → 备份配置 → 升 → 自检 → 不符就回退」。
5. **保留判断**：模型变强 ≠ 我们的工作台自动变强。真正决定产出的是**场景切分 + 记忆沉淀 + 执行层稳定性**——这三样是我们的护城河，不随模型升级而消失。
