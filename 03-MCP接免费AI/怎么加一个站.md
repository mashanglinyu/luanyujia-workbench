# 怎么加一个站 —— 十几分钟的活

> 前提：你已经有**一个能跑的薄壳**（内核与流程共用一份）。加站不需要改流程，只填一个对象。
> 骨架代码在 [`../模板/MCP-站点薄壳.mjs`](../模板/MCP-站点薄壳.mjs)。

---

## 五步

### 第 1 步：准备一个"登录着的窗口"

1. 用**独立的浏览器 profile** 目录（别用你日常浏览器的，会互相干扰）；
2. 手动登录目标站，确认能看到**输入框**；
3. 记住这个 profile 路径 —— 后面填 `profileDir`。

> ⛔ 不要共享一个 profile 给多个站：登录态混在一起，出问题无法定位。

### 第 2 步：量三个选择器

打开页面 → F12 → 分别确认：

| 要量的 | 怎么量 | 坑 |
|---|---|---|
| 输入框 | 点一下输入框，看 Elements 高亮的那行 | 页面上常有**两个**（搜索框 + 对话输入框） |
| 发送 | 多数站支持回车；不支持的找发送按钮 | 有的站回车是换行（Shift+Enter 才是发送） |
| 回答容器 | 发一句话，看新出现的最外层节点 | 要选**一次回答**的容器，不是整个消息列表 |

> 判据：量完当场发一条消息，用 `document.querySelectorAll(sel).length` 确认只命中 1 个。

### 第 3 步：填薄壳对象

```js
export const site = {
  id: 'my-site', name: '某免费 AI', url: 'https://example.com/',
  loggedIn: async (page) => !!(await page.$('textarea')),   // 只有登录后才有
  inputSel: 'textarea',
  send: async (page) => { await page.keyboard.press('Enter'); },
  answerSel: '[data-answer]',
  wait: { firstTokenMs: 20000, stableMs: 1200, hardTimeoutMs: 180000 },
  profileDir: '<你的 profile 目录>',
};
```

### 第 4 步：注册成工具

工具名建议 `ask_<site.id>`，描述里**必须写明**：慢、只适合一次性纯文字任务、不要发机密。

### 第 5 步：跑三条自检

```
① 未登录时：应报"未登录"，不该返回空字符串
② 正常问一句：应拿到完整回答（不是半句）
③ 问一个超长问题：应在 hardTimeoutMs 内给出明确超时错误，而不是无限等
```

## 加站的四个"便宜"与两个"贵"

| 便宜（加站不用碰） | 贵（每加一个站都得重做） |
|---|---|
| 流程代码（输入/等待/取文本） | **量选择器**（对方改版就废） |
| 桥与 IPC | **登录态维护**（掉登录要人工重登） |
| 工具注册格式 | — |
| 超时与错误信息 | — |

> 结论：**加站的成本不在代码，在"维护选择器与登录态"**。
> 所以别一次加 10 个站 —— 加你**每周真的会用**的那 2~3 个。

## 五个站怎么分工（本机实测口径）

| 站 | 留给它的活 |
|---|---|
| **豆包** | 多模态（图片/视频链接理解）、抖音系链接一律给它 |
| **通义千问** | 生图 / 生视频类需求 |
| **DeepSeek** | 代码、长文推理 |
| **智谱清言** | 代码与结构化输出（第二意见） |

> ⚠ 这是**本机实测的偏好，不是绝对结论**：各家能力月月变，选站要看"当前哪个稳"。
> 我们的用法是"同一个问题问 2 站、比一比"（见 [`../08-升级与改造清单/把规矩变成机制.md`](../08-升级与改造清单/把规矩变成机制.md) 里"不花 token 的第二意见"）。

## 一条纪律（写进代码，不只写在文档）

```js
// 机密闸：正文含 密码 / token / 密钥 / 身份证 / 银行卡 / 手机号 ⇒ 拒发
```

这些站是**站外服务**：客户名单、服务器口令、他人隐私、个人档案细节 —— **一律不发**。
把这条判断放在**调用之前**，不要只写在注释里。
