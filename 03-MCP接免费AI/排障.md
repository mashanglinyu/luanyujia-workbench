# 排障 —— 「它明明回答了，但我拿到的是错的」

> 接网页版 AI 的故障有个共同特征：**大部分不报错**。
> 拿到半句话、拿到上一轮的回答、拿到空字符串 —— 看起来都"成功"。
>
> 这一页按**症状**查，别按代码查。

---

## 症状 → 根因 → 修法

| 症状 | 最可能的根因 | 修法 |
|---|---|---|
| **只拿到半句话 / 一句话被截断** | 只等了"文本出现"，没等"文本稳定" | 加 `stableMs`（连续 1~2 秒无变化才算说完），见 [整体架构](整体架构.md) §3② |
| **拿到的回答是上一轮的** | 回答容器选错（选到了消息列表，取到了第一条） | 选**最后一条**回答的容器：`querySelectorAll(sel).pop()` |
| **返回空字符串** | 选器过期 / 未登录 / 页面还在加载 | ⛔ 不要返回空串：改成抛错（"未登录"或"取到空回答（选择器可能过期）"） |
| **"回包来自旧桥"** | 页面里还挂着一份**旧的注入脚本**（热更新后没重载） | 强制重载该窗口；给桥加版本号，版本不符就拒绝回包 |
| **登录态忽然没了** | profile 被别的进程占用 / 站点主动过期 | 用独立 profile；掉登录就**报错让人重登**，别自动重试登录 |
| **弹验证码 / 滑块** | 触发风控（频率过高 or 新环境） | 降频、别并发；弹了就**停**，让人工过一次 |
| **两个问题互相串话** | 同一个站开了两个页面并发问答 | 同站串行；不同站可以并行 |
| **一直等不到回答** | 发送没成功（回车被当成换行） | 确认发送方式：有的站要 `Shift+Enter` 或点按钮 |
| **很慢但能用** | 正常（这就是它的代价） | 别把它放进长任务链路；只做"问一次要一段文字" |

---

## 排查顺序（照着走，别跳）

```
① 这个窗口还登录着吗？      → 手动打开同一 profile 看有没有输入框
② 三个选择器还对吗？        → F12 里 querySelectorAll 各验一次，应只命中 1 个
③ 发送真的发出去了吗？      → 看页面上有没有出现你的提问气泡
④ 等的是"最后一条"回答吗？  → 是不是取到了历史消息
⑤ 等了"稳定"吗？            → 只看"出现"必然拿半句
```

只要 ① 或 ② 不成立，后面全是白调 —— **先确认前提**。

---

## 两个"看起来正常"的陷阱

| 陷阱 | 为什么危险 |
|---|---|
| **返回空字符串当成功** | 上层会理解成"AI 说没有" ⇒ 你排查的是业务逻辑，而真因是选择器过期 |
| **超时设成无限** | 卡住时表现为"界面一直在转"，用户以为在思考 ⇒ 必须有 `hardTimeoutMs` |

## 出问题时的最小证据（贴给求助对象时用）

```
站 id：
是第几个问题之后开始出错的：
窗口登录状态（手动打开能看到输入框吗）：
三个选择器各自命中几个：
最后一次拿到的文本（前 80 字）：
等待参数（firstTokenMs / stableMs / hardTimeoutMs）：
```

> 有这六行，"选择器过期"和"登录掉了"基本一眼能分。
