# 把规矩变成机制 —— 一套系统能不能活过三个月的分水岭

> 这份工作台的宿主说过一句最狠的话：**「把规矩变成机制」**。
>
> 意思是：规矩写在文档里，靠的是**自觉**；机制跑在代码里，靠的是**机器**。
> 一份只有"规矩"的系统，三个月后一定退化成"看心情"。

---

## 1. 一个残酷的判据

> **没有"会失败的检查"的规矩 = 一句口号。**

举例对照：

| 说法 | 是规矩还是机制 |
|---|---|
| 「临时文件要放对地方」 | ❌ 规矩（谁来判断"对"？） |
| 「有个工具，你问它放哪，它直接建好目录」+「有个哨兵会扫违规并 exit 1」 | ✅ 机制 |
| 「清理任务要按时做」 | ❌ 规矩 |
| 「周日 12:35 跑一个巡检脚本，它自己找 + 自己发请求」 | ✅ 机制 |
| 「记得更新索引」 | ❌ 规矩 |
| 「索引体检：未登记 = ⚠，死条目 = ⛔，命中就报」 | ✅ 机制 |

**注意"会失败"三个字**：如果一个检查**永远通过**，它就不是检查，是装饰。

## 2. 五步法：把一条规矩变成机制

```
第 1 步  写清"违规长什么样"
         ── 必须是可判定的（能写成条件），不能是形容词
         ❌「索引要完整」     ✅「文件存在但索引里没这一行」
         ❌「记忆不要太长」   ✅「§〇 超过 4096 字节」

第 2 步  找到唯一的判据出处
         ── 同一个判断只写在一个地方（一个工具/一节规范），别两处各判一次
         ⛔ 两处判据 = 两份结论 = 早晚打架

第 3 步  写一个能 exit 非 0 的检查
         ── 输出必须能说出"差异集合"，不是只给一个 0/1
         ❌「体检通过」
         ✅「⛔ 3 项：未登记 2（a.md / b.md）· 死条目 1（c.md）」

第 4 步  给它一个"应当失败的反例"
         ── ⛔ 这一步 90% 的人会漏，也是最容易自欺的地方
         做法：故意造一个违规样本，确认它会报；再把样本恢复
         判据：**反例不报 = 这个检查是假的**

第 5 步  挂到节奏上
         ── 手动跑的检查等于没跑
         落地：计划任务（每周/每天）· 或"每次改完必须跑"的硬性流程
         再加一条：⛔ 检查失败的输出要进"待办"，不能只躺在日志里
```

## 3. 三个真实例子（这套系统里已经变成机制的）

### 例 1：临时文件只能放三处

| 步骤 | 落地 |
|---|---|
| 违规长什么样 | 临时文件出现在白名单之外的目录 / 目录名没带时间 |
| 判据唯一出处 | 一个 `临时路径` 工具：**问它放哪，它直接建好目录** |
| 会失败的检查 | 一个 `临时哨兵`：扫违规区，有违规 ⛔ 并 exit 1 |
| 反例 | 故意在盘根建个临时目录 ⇒ 必须报 |
| 节奏 | 已挂进全量体检（每周） |

> 关键设计：**"该放哪"不是文档里的一句话，而是一条命令的输出**。
> 人不用记规矩，只要跑那一条命令。

### 例 2：体检 ⛔ 自动进待办

| 步骤 | 落地 |
|---|---|
| 违规 | 体检出现 ⛔ 项，但没人处理 |
| 判据 | 体检结果 JSON 里的 bad 列表 |
| 检查 | 跑完体检 ⇒ 自动把 ⛔ 项追加到待办板（**同一件只许一行**，去重） |
| 反例 | 造一个必然 ⛔ 的项 ⇒ 待办里必须多一行 |
| 节奏 | 体检每周跑；进待办后由"分诊"分派 |

> 这条把"报告"和"行动"接起来了 —— 否则体检报告只会躺在文件里慢慢过期。

### 例 3：回执双向自动销账

| 步骤 | 落地 |
|---|---|
| 违规 | 派了单、对方没回；或对方说"发了"其实没发 |
| 判据 | 一个台账：每条"派出未回执"和"在等我回"都记着 |
| 检查 | 一个工具列出两张单：**我发出没回的 / 别人在等我回的** |
| 反例 | 发一条不唤醒的"派单" ⇒ 它必须出现在"未回执"里 |
| 节奏 | 每次派单后隔一阵自查；收到回执自动销账 |

> 这条解决的是 AI 协作里最贵的隐性浪费：**双方都在等对方**。

## 4. 什么不该变成机制

不是所有规矩都值得机械化。三种情况可以留在"规矩"层：

| 情况 | 为什么 |
|---|---|
| **判断类**（好不好、该不该做） | 没有客观判据，硬写成检查会误杀 |
| **一次性**（这次这样，下次不一定） | 写机制的成本高于收益 |
| **靠人拍板**（要不要花钱、要不要对外） | 这类必须留给人 —— **机制负责"提醒"，不负责"决定"** |

> 判据：**这条规矩能不能写成"条件 + 差异集合"？** 能 ⇒ 机械化；不能 ⇒ 留在规矩层，但要写清"谁来判"。

## 5. 一条成熟的规矩长什么样（自检清单）

一条"真的落地了"的规矩，应该能同时回答这五个问题：

```
① 违规长什么样？            （可判定的现象）
② 谁在判？                  （唯一出处）
③ 不通过时输出什么？        （差异集合，不是 0/1）
④ 怎么证明它真的会报？      （反例）
⑤ 多久跑一次？失败进哪？    （节奏 + 去向）
```

五条答不全 ⇒ 它还停在"口号"阶段。
