## 二、加东西的标准（照着做，不用再问）

### 2.1 加一个**场景**
1. 场景定义：`<DSH根>\外壳\scenarios\<场景id>.json`（面板数组 + `harness` 面板 + `sessionId`）
2. **定位卡**：`scenarios\<场景id>-context.md`（身份与职责 / 面板地图 / 触发词→定位 / 流程 / 铁律 / 上次进度）
3. **登记身份索引**：`scenarios\_场景身份索引.md` §二（场景id · 面板id · 面板名 · 会话名 · sessionId · 定位卡 · 技能）与 §五（**记忆写回哪里**）
4. **专属技能**：`引擎\.dsh\skills\<技能名>\SKILL.md`（见 2.2）；没有技能也要在索引里写"无专属技能"
5. **长期记忆**：`引擎\场景项目信息\<场景文件夹>\项目信息.md`（见 2.4）
6. 生效：改 `scenarios\*.json` ⇒ **切一次场景**（不是点 ⟳）；新场景标签 ⇒ **重启 GUI**

### 2.2 加一个**技能**
- 位置：`引擎\.dsh\skills\<技能名>\SKILL.md`（**只有这里引擎才自动加载** ✓）
- front-matter：允许 **`name` / `description` / `whenToUse`**（三个字段都把**触发词 / 什么时候该用它**写清 ✓）
  - `name` + `description` **必填**（缺一个整条技能会被引擎忽略）；**`whenToUse` 是可选的、引擎确实支持** —— 它**不进每轮注入的 `<available_skills>` 目录摘要**（引擎渲染目录只用 name+description）⇒ **不增加固定开销**，可以放心写
  - 另可用 `disable-model-invocation` / `user-invocable`（布尔，管"谁能唤起"）与 `metadata`（对象）；⛔ 别用驼峰旧写法（`disableModelInvocation` / `modelInvocable` 等会被引擎直接判错）
  - ⚠ **本节判据 2026-10-16 改过一次、为什么**：旧文写"只准 `name:` + `description:` 两行"，与引擎事实不符（体检因此一直报"8 个技能 front-matter 多了字段"）。核实处：`引擎\packages\skill\skill-filesystem\src\index.ts`（front-matter 解析，取 name/description/whenToUse + invocation + metadata，其余字段忽略）+ `引擎\packages\skill\tool-skill`（目录渲染，**不含** whenToUse）；技能目录里多份也一直在用 ⇒ 按事实改成上一条（**那 8 个技能一个都没动**）
- 体积：`SKILL.md` **≤ 12 KB**；细节拆到同目录 **参考文件** `<主题>.md`（首行写 `> 归属技能：<名> · 从 SKILL.md 拆出（日期）`）
- ★★ **技能要长大时的正路 = 拆子技能，不是硬压**（2026-10-16 用户拍板 —— 他问"技能确实需要大一点，但强制压缩会不会导致基础功能丢了？"，选定「**技能要长大 ⇒ 拆子技能**」）：
  - **主技能 `SKILL.md` 只留四样**：**导航 + 判据 + 铁律 + 触发词**；把**长流程 / 大清单 / 大案例**独立成**子技能**目录
    `引擎\.dsh\skills\<主技能名>-<子主题>\`（同样要 `SKILL.md` + front-matter 的 `name`/`description`/可选 `whenToUse`）。
  - **子技能的 `description` 必须写清"什么时候该用它"** —— 引擎渲染 `<available_skills>` 目录**只用 name + description**（`whenToUse` 不进目录摘要），
    所以会不会选中它**全看这一行**：写症状、写场景、写触发词，别只写"XXX 的细节"。
  - **主技能里必须留一行指路**：`要 <做 X> 时，用子技能「<子技能名>」`（只写个子技能名不算，见 §2.4 的"触发句"）。
  - **子技能也要登记** `引擎\.dsh\skills\_索引.md`，那一行要写明**它属于哪个主技能**。
  - ⚠ **技能目录条数 = 每轮固定开销**（`<available_skills>` 每轮都注入，`全量标准化体检.mjs` 报告里就报这个数）⇒ **别滥拆**：
    拆出去的是"又长又少用"的内容，天天要用的主干留在主技能。
  - ★ **正路是"拆"，不是"删/压"**：为了把体积压回 12 KB 而删判据、删命令原文 = **静默丢功能**（什么能搬、什么绝不能搬，见 §2.4）。
  - 机械抓手：`node <DSH根>\工具\技能完整性体检.mjs` —— 孤儿参考件 / 指针没写"什么时候读" / 判据被搬走没人指 / 缺归属行 / 超 12 KB / `references\` 复数，逐条点名到行。
- 铁律：**先 grep 再改**；**同名/同字段不许重复**（查重器见 §4）；技能目录**只放真技能**（说明文档放 `<工作区>\_文档\`）
- 生效：**热加载** ✓ 无需重启

  `§五`/`§八`/历史轮次/按日期的旧交接**一律搬进同目录 `归档\§<编号>-<名字>-<YYYYMMDD>.md`**，主文件原位置只留一行指针
  （例：`## §五 决策与坑（2026-10-15 归档 → `归档\§五-决策与坑-20261015.md`，要查先 grep 那个文件）`）。
  ⛔ **只搬不丢**：搬完跑 `node <DSH根>\工具\核对拆分.mjs`（逐行核对"原文每个非空行都还在新文件里"）与 `索引体检.mjs`；

- ★★ **拆分规矩之一：什么能搬、什么绝不能搬**（2026-10-16 用户拍板；**技能 `SKILL.md` 与记忆 `项目信息.md` 用同一条**）：
  - ✅ **能搬出去**（＝读不读都不改变动作）：**解释 · 背景 · 长篇清单 · 历史案例 · 例子 · 排障经过**。
  - ⛔ **绝不能搬走**：**判据 · 阈值 · 命令原文 · 执行顺序 · 红线 · 触发条件** —— 这六样一搬走就是**"功能静默丢失"**：
    文件都在、一个字没删，但干活时**没有任何东西提醒 AI 去读它** ⇒ 表面完整、实际不会执行。
  - **一句话判据**：这条内容"**读不读会改变我下一步动作**"吗？**会 ⇒ 必须留在主文件**（留不下就至少留等价判据）；不会 ⇒ 才搬。
- ★★ **拆分规矩之二：移出内容必须留"触发句"**（2026-10-16 立；**技能 `reference\` 与记忆 `归档\` 同一条**）：
  主文件原位置**不许只留一行路径**，必须写清"**什么时候去读**"，格式 ``要 <做某件事> 时，读 reference\<文件>.md §<节>``

  ⛔ 只写 `→ reference\x.md`（或只写 `见 归档\…`）**等于没写**：指针不带"什么时候"，人和 AI 都会跳过它。
  机械判据：`node <DSH根>\工具\技能完整性体检.mjs` 第 2 条（指针行/同段无 `时/前/若/当/遇到/需要…` ⇒ ⚠）。

> 用户原话：「有没有办法不打包了？以后真变成软件再打包，**不要让我的工作台受影响**。」
> ⇒ 本机工作台的正式形态就是**不打包**；"打包"这件事只在**给别人装**（`<项目目录>\DSH一键安装` 那条线）时才做。

**这个形态靠两件事撑着**（缺一个就退化成"改代码要重新打包"）：

| 撑着它的东西 | 保持成什么样 | 为什么 |
|---|---|---|
| `启动器\win-unpacked\resources\app` | **目录联接** → `<DSH根>\外壳` | 工作台读的就是真源码 ⇒ 改 `renderer\*.js` 点 ⟳ / 跑 `刷新面板.mjs` 即生效 |
| `启动器\win-unpacked\工作台.exe` | **打包时那一个原文件，不许替换/改动/改名/改版本号**（**工作台运行时更绝对不许**） | 2026-10-15 实测：用 `rcedit` 改它的版本资源 ⇒ 渲染进程全线 `launch-failed exitCode 57`、**所有面板灰白**；更坑的是 **壳进程只要经历过"自己的 exe 被改名/替换"，此后一个子进程都起不来**（当时 12 个进程启动时间全停在那一刻），**只能重启工作台**才能恢复 |

- ⛔ **禁止**：跑 `scripts\打包.mjs`（除用户明确要求）· 替换/改名/改图标/改版本资源那个 exe · 把 `resources\app` 换成打包副本。
- ✅ **想改界面**：直接改 `外壳\` 里的源码 → 点 ⟳ 或 `node 外壳\scripts\刷新面板.mjs [all|场景id]`；**永远不需要打包**。
- ✅ **想改版本号显示**：改 `外壳\package.json`（`node scripts\同步版本.mjs`）与 `renderer\renderers.js` 的 `ADAPTED_ENGINE`；**exe 文件属性里的那个数字不用管**。
- **机械抓手**：`node <DSH根>\工具\入口哨兵.mjs`（基线 `说明\工作台入口基线.json`）—— 比 exe 的 SHA256、比 `resources\app` 还是不是联接、比快捷方式指向；
  **每周日 12:30 随 `稳定体检.mjs` 自动跑**，破了就 ⛔。用户批准过的形态变更 ⇒ `入口哨兵.mjs --save` 更新基线。
- **面板变白 / 卡住时的排查顺序**（2026-10-15 实战总结，按这个顺序别乱试）：① `外壳\server.log` 找 `launch-failed` / `did not activate` / `server exited`
  → ② **看工作台进程的启动时间是不是全停在某一刻**（`Get-Process | Where-Object ProcessName -like 'DeepSeek*' | Select Id,StartTime` —— 是 ⇒ 壳已经起不了子进程，**只能重启工作台**）
  → ③ 壳还健康时才用 `node 外壳\scripts\刷新面板.mjs all` 让面板自己重载 → ④ 请**用户**关掉工作台再打开（⛔ 会话不许自己关 GUI / 重启引擎）。

### 2.10 文档生命周期（**别让没用的字堆着**：新增 → 四词状态 → 到期处置 → 复核）

> 用户 2026-10-16 的要求：「及时清理历史文档、更新需要的文档、合并杂乱的文档、归档有历史价值的文档。」
> 配套体检：`node <DSH根>\工具\文档体检.mjs`（未登记 / 死条目 / 到期 / 体量红线 / 疑似重复 / 过程件堆积）。

**① 状态四词**（写在索引或台账的"状态"列，**只用这四个**）：

| 状态 | 含义 | 复核期 |
|---|---|---|
| `活` | 每次干活都读写的（记忆/规范/入口） | 每次动就刷日期 |
| `常备` | 半年内还会用（手册、清单、脚本说明） | **180 天** |
| `留档` | 只作证据，不再更新（报告、诊断、演练记录） | 不催，但到期该归档 |
| `待清` | 已经没用了，**一周内**必须处理掉 | **7 天** |

**② 到期四选一（处置动作，别只是"留着"）**：
`更新`（内容还活，改到最新）/ `合并`（同类小文件并成一份，**优先这个**）/ `归档`（挪到留档位）/ `清`（删或进回收站）。
**归档落点**（不许另创目录名）：场景记忆 → `<场景记忆目录>\归档\§<节>-<名字>-<YYYYMMDD>.md`；跨场景文档 → `<工作区>\_归档\<主题>-<YYYYMMDD>\`；引擎侧历史 → `引擎\备份\<主题>-历史归档.md`（追加）。
**合并/改名/删除 ⇒ 同一步改索引那一行**（§2.7 三条硬规矩之一），并把动作写进该索引的「处置记录」（只追加：日期 + 动作 + 为什么）。

**③ 命名**：用途 + 时间（`目录基线.json`、`换机移植演练-20261015.md`）。⛔ 禁 `最终版` / `v2` / `副本` / `新建文档`；同一主题**只留一份**（要保留历史就进 `归档\`，别并排放两份）。

**④ 体量红线**（超了就是"该拆"的信号）：场景 `项目信息.md` 主文件 **≤25 KB**、`§〇` **≤4 KB**；技能 `SKILL.md` **≤12 KB**；定位卡 **≤25 KB**。
拆法：按 §2.4 把旧节搬 `归档\` 并在原位留一行指针（**只搬不丢**），搬完跑 `核对拆分.mjs` 验"丢失 0 行"。

**⑤ 节奏（可持续的部分）**：
- **每周日 12:30**：`稳定体检.mjs` 顺带跑 `索引体检` + `文档体检`（未登记 / 死条目 / 到期）—— 2026-10-16 用户定「不需要每天体检」。
- **每月 1 日 05:00**：计划任务 `DSH-月度文档整理` 生成 `备份\维护报告\文档整理-<YYYYMM>.md`（当月该更新/合并/归档/清的清单 + 建议谁去做）。
- **跨目录总入口**：`说明\_文档台账.md`（哪些大文档、谁负责、什么时候复核、过期怎么办）。
- **反馈回路**：每次处置都落"处置记录 + 复核日期"，**下次体检按新日期算** —— 这样文档池只会越用越干净，不会烂回头。

**⑥ 文档密集目录必须有索引（★ 2026-10-17 立，起因见下）**

> **用户 2026-10-17 实测投诉**：「**很多会话在一些有大量复杂文档的文件夹不建立索引，规矩失效了**」。
> **取证**（只读扫描 `<项目目录>` / `<项目目录>` / `<素材目录>` / `<DSH根>\自我复盘` / `<工作区>`，直接子文档 ≥15）：
> `题库\_派活` **284 份无索引** · `题库\_备份` 54 · `题库\_难度` 42 · `项目信息\归档` 36 · `任务清单\排查` 34 · `项目信息\旧版存档` 29 · `<DSH根>\工具\webai体检` 15 —— **9 个密集夹里 7 个没有索引**。
> **根因不是会话不守规矩，而是旧 §2.10 只管"全局台账 + 每场景一份索引"，从没要求项目内的密集子目录建索引，也没有任何体检会报** ⇒ 规矩"看着在、实际没抓手"。

- **判据（写死，用数字）**：某个**常驻目录**（不是 `_临时`）的**直接子文档 ≥ 30 个**，或**直接子文档 ≥ 8 个且合计 ≥ 500 KB**，或**同一主题文件 ≥ 10 个**（如 10 份派活/10 份日报）⇒ 该目录**必须有 `_索引.md`**。
  ⚠ **最小份数 8 是必须的**（2026-10-17 实测裁决）：不加它，`≥500 KB` 会把"1 份 249 MB 的图鉴""1 份 1.1 MB 的 toolchain"这类**单文件大目录**误判成"文档密集"（初版 52 个密集里 30 个是这种 2~7 份的目录）—— 单文件大目录只需一条 README 说明，不必逐文件索引。
- **索引文件形态**：`<目录>\_索引.md`，首行一句"这是什么目录、按什么命名、谁在用"，然后**一行一条**：`文件名 | 是什么 | 状态（活/常备/留档/待清） | 最后更新`。
  ⚠ 不必逐字精读每份文件：**标题/首行 + 日期**即可（**别为了索引把整个文件夹读进上下文**）。
- **豁免（写死，避免把索引变成负担）**：① `_临时\<会话名>-<时间>\` 一次性过程件 **免** ② `node_modules`/`dist`/`unpackages`/`__pycache__`/缓存 **免** ③ `_备份` / `旧版存档` / `归档` 这类**历史件不逐条索引**，但**父目录的索引里必须有一行**写明"这里是什么历史、按时间命名、何时可以清"。
- **三个触发点**：① 在一个目录里**新建到第 30 份文档**时 ⇒ 建索引（别等 284 份才补）② **接手/开场**发现目标目录密集且无索引 ⇒ **先补索引再干活**（30 秒的事，省后面几小时）③ **移动/归档/改名** ⇒ 同一步改索引那一行（同 §2.7 的三条硬规矩）。
- **谁负责**：该目录归属的**主场景**（OA → `oa-ai`；自我复盘 → `sr-ai`；工具与工作区 → `dg-dsh`；清理/归档 → `pc-cleanup`）；跨场景的写进 `三-跨场景协作.md` 判据表。
- **机械抓手（规矩没有抓手＝不算立）**：`node <DSH根>\工具\索引体检.mjs --dense`（2026-10-17 加）扫常驻根，按上面判据列出"密集但无索引"的目录并给建议文件数；接进 `全量标准化体检.mjs` 的 📚 类；退出码 `0` 干净 / `1` 有 ⚠ / `2` 参数错。


**⑥ 例外：项目自有成熟索引 ⇒ 不逐文件复制进 DSH 台账**（2026-10-16 立，裁定 `oa-ai` 的提问）：
- 一个项目目录**自己已经有成熟索引**时，DSH 台账**只登记"入口"一行**（指向该项目的索引），**不逐文件往台账抄** —— 同一批文档抄两遍，台账会写胖，且两份必然漂移。
- **判定三条**（全满足才算已登记）：① 该项目目录在**白名单** `<DSH根>\说明\自有索引项目.json` 里；② 该目录的那个**索引文件真实存在**（当场验存在性）；③ DSH 台账里有**一行指向该索引**的入口行。
- 满足三条 ⇒ 该目录下的文件**视为已登记**（体检打一行 ℹ「按 §2.10 例外」放行，**不静默**）；**不满足**（索引不在 / 入口行不在）⇒ **照旧逐文件要求登记，不许拿"我有自己的索引"当借口**。
- **新文档的登记义务不变**：新建文本仍要登记；变的只是登记**落点**可以放项目自有索引（**DSH 台账里那行入口行**管"这个目录归谁、什么时候复核"）。
- ⛔ **判据是机械的**：两个体检（`文档体检.mjs`、`基础体检.mjs`）都读那份 json 按上面三条跑；**例外不是"看一眼就算"**，索引删了/入口行没了 ⇒ 当场退回逐文件登记。

### 2.12 免费 AI 顾问通道（**集思广益，但要合理适度**）

> 用户 2026-10-16 定：「利用好左上角的 ai 通道（deepseek、豆包、千问）做一个**稳定的对话通道**，出方案的时候可以发给它们**轮询意见集思广益合理采纳**，要**合理适度**。」

**① 是什么**：工作台顶栏左上角已开着的 5 个免费网页版 AI（`deepseek` / `doubao` / `tongyi` / `chatglm` / `kimi`），
经 `外壳\scripts\webai.mjs` 桥接，**不花 API token**。它们看不到本机磁盘、没有记忆、不能验证 ⇒ 是**第二/第三意见**，不是代工。

**② 一条命令**（**别自己写循环逐个 ask** —— `顾问团.mjs` 会把 2~3 份回答收成**一份 `_汇总.md`**，你只读这一份）：

```powershell
node <DSH根>\工具\顾问团.mjs "<问题.md 或 问题文字>" --n 3 --round2 --from <你的场景>
```

产物：`<工作区>\_webai产物\顾问团-<YYYYMMDD-HHMM>\`（各站原文 + `_问题.md` + **`_汇总.md`** + 第二轮的 `_第二轮-<站>.md`）。
`--round2` = 再让一站读另外两站的意见，给「共识 / 分歧 / 最有价值的点 / 怎么取舍」——**"集思广益"的收口就在这一步**。
`--mode critique`（默认，挑毛病+给改法）/ `answer`（直接答）/ `review`（逐条评审）/ `--raw`（原样发）；`--dry` 只看计划不碰桥。

**③ ⛔ 机密闸（脚本硬拦）**：正文含 密码 / token / 密钥 / 身份证 / 银行卡 / 手机号 ⇒ **拒发**，`--force` 也不放行；
IPv4 / 邮箱 / "账号" 只警告 ⇒ **自己判断**。它们是**站外服务**：客户名单、服务器口令、他人隐私、个人档案细节**一律不发**。

**④ 「合理适度」的尺子**：一次 **2 站**（默认）/ **3 站**（只给不可逆、影响面大的方案）/ ⛔ **不超过 3**；
**该问**＝要取舍的方案、要找漏洞、要第二意见；**别问**＝事实性小问题、长任务/多步骤开发、要看本机文件的活、同一问题反复问（**同一份汇总在手就别再问**）。
**采纳三原则**：它的建议**自己核过**再落文件；**采纳项写进文件才算数**（汇总里那三栏「共识 / 分歧 / 采纳项」必须填）；⛔ 不许把它的回答**当真结论**直接写进项目文档。

**⑤ 稳定的三个前提**（不满足先修，别硬试）：顶栏那几站的窗口**已经开着**（桥**绝不开新窗**，报 `[ensure] 窗口没开` ⇒ 请用户点一下那颗图标）·
窗口**可见/在渲染中**（最小化会读成 0 字）· 站点已登录没卡验证码。脚本内置**快速失败重试**（<30s 挂掉才重试，超时不重试）且**一站挂不影响其余站**。
技能细则：`引擎\.dsh\skills\webai-offload\SKILL.md`（§2 顾问团 + §5 红灯）。

### 2.13 帮手会话（助手）（**活重就开帮手 · 主会话调度 · 必须登记**）

> 用户 2026-10-16 定：「你现在在任务栏顶做一个按钮，这个按钮就叫助手，点击后**按场景分类**，可以看到他们各自的助手……有时候有些 ai 的活很重，这样我也方便管理查看，**定好规矩可以标准化复用**。」

**① 是什么**：某场景**活重 / 可切片 / 要并行**时（这三个就是触发信号），给它开 **1~N 条帮手会话**，由该场景**主会话**调度。⚠ **帮手不是新场景**：⛔ 不进 `外壳\scenarios\_场景身份索引.md` §二 名册、⛔ 不建定位卡、⛔ 不建场景记忆 —— 它只有一份交接文档（④）。★ **身份署名（2026-10-17 身份统一）**：帮手在跨场景消息里显示为「场景名（帮手标题）」，例 `<客户> OA 系统运维（<客户>助手1）`（由 `_共用-谁在发.mjs` 的 `resolveSender()` **现读** `外壳\data\助手会话.json` 得出；优先级 帮手 > 主会话 > 未登记）。
**② 命名**：`<场景简称>助手N`（例：`<客户>助手1`、`<客户>助手2`，场景简称取该场景一眼能认的词；末尾编号可省）—— 名字**要以「助手」结尾、后面只许跟编号**；`助手会话.mjs` 按这条硬校验，不合规直接拒。
**③ 工作目录**：默认 `<DSH根>\工作区`（**新工作区**；建会话时**不给** `--keep-cwd`）；场景自己的资产仍按**绝对路径**引用（例 OA 用 `<客户项目目录>\`，`oa-ops` 的记忆/项目文件一律别搬进工作区）。
**④ 交接文件**：每个帮手**一份** `引擎\场景项目信息\其他会话临时项目信息交接文档\<名字>-<YYYYMMDD-HHMM>.md`（照同目录 `_模板.md`，文件名＝**名字 + 时间**），写清**五件事**：**身份 / 开场读什么 / 边界 / 谁调度 / 回执规矩**。这份文件＝它**唯一的记忆落点**（没场景记忆，别往别人的 `项目信息.md` 里塞）。
**⑤ 登记（硬）**：建 / 删帮手 ⇒ **必须**跑 `node <DSH根>\工具\助手会话.mjs --add|--remove … --go`（**默认干跑**，不写盘；`--list` 随时看现状）。**不登记＝工作台顶栏「助手」按钮里看不到＝等于白开**。数据源 `外壳\data\助手会话.json`（顶栏按钮**只读它**；⛔ 别手改，一律走工具）。
★ **2026-10-16 起：新增帮手不用手工五步 ⇒ 一条命令**（用户点名「定好规矩标准化复用」；`助手会话.mjs --onboard` 把 ②③⑤ 与"解析目标会话"四步合成一条）：

```
node <DSH根>\工具\助手会话.mjs --onboard --scene <场景id> --title <场景简称>助手N --id <sessionId> --go
```

默认干跑（只打印四步计划 + 开头正文预览，**不写一个字节、不发一条消息**），`--go` 才真做：它自动 **① 解析目标会话**（`--id` 直给，或只给 `--title` 就按会话列表找、重名/找不到都拒）→ **② 从「同场景样板帮手」那份交接文件派生**新文件 `<名字>-<YYYYMMDD-HHMM>.md`（只换名字/id/时间/资产根/技能名，写完 `Test-Path` + 字节数自证，⛔ 旧文件只改名 `*.replaced` 不删）→ **③ 发开场指令**（中文一律写临时 `.md` 再投，与 `派单.mjs` 同一套 `session/prompt` 配方；`HTTP 200 + accepted=true` 才算送达）→ **④ 登记注册表**（复用 `--add` 的三条硬校验）。结尾固定一行小结：`新增帮手：<名字> · <id> · 交接文件 <路径> · 开场指令 HTTP <码> · 注册表 <前>→<后> 条`。
两条它**自己算、不许你猜**的东西：**场景资产根**取自 `外壳\scenarios\_场景身份索引.md` **§五 写回点表**（例 `oa-ops` ⇒ `<客户项目目录>\项目信息\`），**专属技能名**取自 §二 名册最后一格（例 `oa-ops` ⇒ `langchen-oa-ops`）；要覆盖就 `--asset` / `--read` / `--template`（默认样板＝交接文档目录里那份干净的「<客户>助手2-20261016-1945.md」，⚠ 别拿被自己刷过 §〇 的助手1 那份）。
**与 `建助手.mjs` 的分工（2026-10-16 定，别重复造）**：**`建助手.mjs` 管"从零开一条新会话"**（`session/create` + 改名 + 塞开场消息 + 调本工具登记）；**`助手会话.mjs --onboard` 管"给已存在的会话补身份"**（派生交接文件 + 发开场指令 + 登记）。**注册表写入永远只有 `助手会话.mjs` 这一个写入器** —— `--onboard` 遇到「**已登记过的 id**」一律**拒**（这正是防重复的闸门），要给已登记的会话重做就得先 `--remove`。

**实操样板**：2026-10-16 20:23 用它把「<客户>助手3/4/5」一次接上正轨（三条各 8,569 B 交接文件 + 开场指令 HTTP 200 accepted=true + 注册表到 5 条；`--list` 复核 1 场景 / 5 条帮手 / 死条目 0；`--check` 复核 ⛔0）。

   - **末行必须写**：`【结束】`（＝"我方这条说完了，不再补充"）。

### 2.14 整树部署铁律（**整棵树推上去 / 盖过去之前，先打一次只读差异**）

> 来源：**`oa-ai` 2026-10-16 实测**（<客户> OA）。`deploy_backend.py` 传的是**整棵本地后端工作树** —— 一个代理在改 `assess.js`、另一个正在改 `quiz.js` / `quizGen.js`，**谁单独跑部署，就会把对方没验完的半成品传上线**。

**① 适用范围（通用，不限 OA、不限部署）**：任何「**把一整棵树推上去 / 盖过去**」的动作 —— 部署、发布、同步、批量覆盖、`robocopy /MIR` 之类，动手前**必须先做一次只读预检**（只比对、不上传、不重启）。
**② 预检看什么**：打出「**本地与目标之间的差异集合**」，再对照「**这次我自己改了哪些文件**」。OA 的抓手＝`deploy_backend.py --check-only`（它的实测：先预检确认"与线上不同的只有我这一个文件"再真部署，**比"我记得没别人在改"可靠**）。
**③ 判据（机械的）**：差异集合 **==** 自己的改动集合 ⇒ **才可以真做**；差异里出现**不是自己改的**文件 ⇒ **⛔ 停手**，先通知那个文件的主人（`node <DSH根>\工具\派单.mjs --to <会话> --file <消息.md> --go`），**别替它上线**。
**④ 做不到预检就先补预检**：没有 `--check-only` 这类只读开关的部署 / 同步脚本 ⇒ **先补一个开关，再部署**（这就是"标准化"该做的事）。
**⑤ 部署后再打一次差异**：若又冒出**别人的**文件，说明**有并发者在飞**，**立刻互相通知**。★ `oa-ai` 实测正是这样照出来的：部署完再比对，diff 变成 `quiz.js` / `quizGen.js`。
**⑥ 与 §2.13 呼应**：**帮手并行干活时这条尤其容易踩**（多个会话同时在改同一棵树）；道理与《测试数据规矩》§四 ⑫②「一个工程不许两个代理同时改」同源。

### 6.1 上下文压力与 413：命令、数字、口径
**★ 换模型＝换窗口（2026-10-18 立，隐患清单 A5）**：窗口是 **per-provider** 的（`deepseek-official` 1M／线 800k · `qianwen`/`fwj`/`maben` 262,144／210k · `codingplan` 160,000／128k）。
给某个面板换模型后，**同一个会话的可用上下文立刻变成新窗口的 0.8**：
- 从 1M 换到 160k ⇒ 原本只占 30% 的会话**瞬间变 413**（不是变卡，是真超限）。
- **换模型前必做**：`node "<DSH根>\引擎\.dsh\skills\context-overflow\ctx.mjs" --all`，看该会话**当前用量** vs **新模型窗口**；用量 > 新窗口 × 0.8 ⇒ 先 `/compact`（或换会话）再换模型。
- ⛔ 别拿"以前在 1M 上跑得好"当依据 —— 那是旧窗口的账。


**413 是什么**：界面出现 `本轮运行失败 · DeepSeek Messages request failed (413) INVALID_REQUEST`，
真实含义是 **`context_length_exceeded`** —— 这一轮要发出去的上下文超过了模型的真实上限（不是网络问题）。

**先试引擎自带的压缩，别急着换会话**（2026-10-15 复核后**废止**旧口径「不要指望 `/compact`」「413 不可恢复」）：
现行引擎（α.2）自带 —— `compaction-basic` 压力到 `floor(min(W×0.8, W−O−headroomTokens))` 自动压缩（headroom 默认 **65536**，**支持按模型覆盖阈值**）；
**`/compact` 命令**（`command-compact`：未到阈值也能压，会报压缩了多少条/省了多少 token）；工具结果先过 `tool-result-pruner`；大图走 `compaction-image-offload`；
**确认溢出后还有 `maxOverflowRetries` 自动重试**（出处：`packages\compaction\compaction-basic\README.md`、`docs\subsystems\compaction.zh.md`）。
⇒ **先敲 `/compact` 或直接再发一条让它压**；只有它明确报"不可用 / 失败"、或压完**仍然** 413，才走分叉或新开。
真到那一步的两条路：**在该会话较早的一条已完成消息上「分叉会话」**（只带走前半段，成果留得住），或**新开会话**（价值已落文件就不亏）。

**"到压缩线"绝不是换会话的理由**（2026-09-25 用户投诉后立，别再用它劝人换会话）：没到真超限（还没 413）时，引擎到线会**自动压缩并继续**，**任务可以一直做到底**；

### 6.4 索引与文档台账：判据、触发点、豁免

### 6.9 GPU 优先：唯一判据与三类可加速的活（2026-10-18 宿主：「直接从根源修改让整个工作台智能体优先使用 GPU」）

> **先说清边界**：这个智能体的**大部分活跟 GPU 无关**（对话/推理都是调远端 API；引擎是 Node）。
> **真正能用 GPU 的只有三类**：① **OCR**（`rapidocr` + onnxruntime）② **视频编码/渲染**（ffmpeg **NVENC**）③ **三维**（Blender / ComfyUI，本来就各自用 GPU）。
> 所以"优先用 GPU"不是到处硬写 `_nvenc`，而是**一处探测 + 一处策略 + 各工具来问**。

**唯一判据：`<DSH根>\工具\GPU优先.mjs`**（⛔ 别在别处另写一套检测）

```js
import { probe, videoEncoder, nvencArgs, shouldUseGpu } from '<DSH根>/工具/GPU优先.mjs';
videoEncoder('h264')      // => 'h264_nvenc' 或 'libx264'（显存不够/无 NVENC 自动降级，⛔ 绝不因此编不出来）
nvencArgs('h264', 20)     // => ['-c:v','h264_nvenc','-preset','p5','-tune','hq','-rc','vbr','-cq','20','-b:v','0']
shouldUseGpu('ocr')       // => { ok, why }（显存门槛：ocr 900 / 视频编码 600 / 渲染 2500 MB）
```

**硬规矩**：
1. **先问再上**：任何要用 GPU 的地方，先 `shouldUseGpu(task)`；`ok === false` 就**照 CPU 跑**，并把 `why` 记进日志（⛔ 不许"试一下不行就崩"）。
2. **降级必须无损**：`videoEncoder()` 拿不到 NVENC 就返回 `libx264`；OCR 拿不到 CUDA provider 就 `CPUExecutionProvider` —— **功能不能因为 GPU 不可用而失败**。
3. **显存是共享资源**：ComfyUI/Blender 在跑时，余量可能不够 ⇒ `shouldUseGpu` 会拦住；⛔ 不许自己去挤。
4. **别重复造判据**：检测逻辑只在 `GPU优先.mjs`；体检的「GPU」一项也只读它的 `--json`。

**★ 优先 ≠ 无条件（2026-10-18 实测修正，最重要的一条）**：GPU **可能更慢** —— 必须**实测再定**，⛔ 不许因为"有 GPU"就切过去。

| 脚本 | 旧（libx264） | 新（nvenc） | 结论 |
|---|---|---|---|
| `douyin.mjs` | 5.128 s / 8.1 MiB | **1.734 s** / 11.6 MiB · PSNR 47.09 dB | ✅ **2.96×**，保留 GPU |
| `finish.mjs` | 2.232 s / 6.2 MiB | **1.816 s** / 15.7 MiB · PSNR 45.00 dB | ✅ 1.23×，保留 GPU（体积 2.5× 待调 CQ） |
| `web.mjs` | **5.774 s** | 7.515 s（**0.77×**）· PSNR 37.14 dB | ⛔ **已改回 x264** —— 瓶颈是 `-vf hqdn3d` **CPU 滤镜**，不是编码 |

**判据**：`s/page` 或 `s/条` 实测 **GPU 更快才切**；**总耗时**变慢就回 CPU（哪怕编码那一步更快）。滤镜/解码/IO 是 CPU 活时，GPU 只换了其中一环 ⇒ 收益可能被吃掉。

**两个实战坑（都已绕过，别再踩）**：
1. **`import` 绝对路径要写 `file:///`**：`import "<盘根>:/…/GPU优先.mjs"` 在 Node 24 报 `ERR_UNSUPPORTED_ESM_URL_SCHEME`（`E:` 被当成协议）⇒ 写 `import "file:///<盘根>:/…/GPU优先.mjs"`。
2. **nvenc 的 `-level` 别乱带**：`-level 4.2` 对 1440p60 会报 `Invalid Level` ⇒ nvenc 分支去掉 `-level`，`libx264` 分支保留原参数。
**实测现状（2026-10-18）**：RTX 4060 Laptop 8 GB · 驱动 617.42 · **NVENC h264/hevc/av1 全有**（ffmpeg 在 `ffmpeg.exe`）；OCR 现役是 `rapidocr_onnxruntime 1.2.3`（**这版没有 use_cuda**）⇒ 要上 GPU 必须走 `rapidocr 3.x` + `onnxruntime-gpu`，方案见 `题库\_拆解\_scripts\OCR-GPU方案-20261018.md`。
