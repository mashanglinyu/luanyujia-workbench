# 四 · 身份索引怎么建 —— 「我是谁」的唯一对照表

> **这篇解决一个问题**：你的工作台里挂着 10 个常驻 AI 会话，而**引擎不按场景注入任何东西** ——
> 会话打开时它并不知道自己是"哪个场景"。你不告诉它，它就会猜；一猜就会串台。
>
> 所以需要一张表：**场景 ↔ 面板 ↔ 会话 ↔ 定位卡 ↔ 技能**。会话开场查表认领自己，30 秒搞定。

---

## 1. 为什么不能靠"记忆"或"猜"

| 做法 | 结果 |
|---|---|
| 让 AI 自己从对话历史里推断 | ❌ 换会话就断片；旧会话的结论还会被当成事实（"别信会话记忆里的旧结论"） |
| 靠在开场消息里写"你是 XX 场景" | ⚠️ 能用，但**换会话/分叉时容易忘**，而且面板那边改了你不知道 |
| **查表 + 定位卡** | ✅ 唯一可靠：表是数据，卡是职责；两者都不在会话里，换多少次会话都还在 |

> 一句话：**身份必须是"文件里的事实"，不能是"上下文里的印象"。**

---

## 2. 表长什么样（7 列，一列都别省）

| 场景 id | 面板 id | 面板标题 | 会话名（`pinTarget` 首项） | 会话 id | 定位卡 | 主技能 |
|---|---|---|---|---|---|---|
| `<场景id>` | `<面板id>` | AI·`<中文名>` | `<会话名>` | `session-00000000-0000-0000-0000-000000000000` | `<DSH根>\外壳\scenarios\<场景>-context.md` | `<技能名>` 或 `—` |

七列各自的用途（缺了会出什么事）：

| 列 | 谁在用 | 缺了会怎样 |
|---|---|---|
| 场景 id | 引擎（`scenarios\*.json` 的文件名）、脚本 | 脚本找不到场景 |
| 面板 id | 派单/通知/刷新面板（`--to <面板id>`） | 别的场景喊不到你 |
| 面板标题 | 人看的（切场景时顶上那个标签） | 无伤，但你自己会认错 |
| 会话名（`pinTarget` 首项） | 引擎按名字找会话 | **会话绑定失效 = 切场景时串台** |
| 会话 id | 引擎按 id 精确找会话（**唯一权威**） | 同上；换会话后不同步就会指到旧会话 |
| 定位卡 | 该场景的职责/资产/铁律/进度 | AI 不知道自己该干什么 |
| 主技能 | 该场景的专业流程 | AI 会用通用办法硬干专业活 |

> ⚠️ **数据源以 `scenarios\*.json` 为准**：表与 json 不一致 = 表过期，不是 json 错。

---

## 3. 怎么建（顺序别反）

```
① 先在 scenarios\ 里放一份 <场景>.json（场景配置：面板、布局、绑定的会话）
② 再从 json 里把「面板 id / 会话名 / 会话 id」抄进这张表 ← 别手打，抄
③ 然后写定位卡 <场景>-context.md（职责 / 资产地图 / 触发词 / 铁律 / 上次进度）
④ 最后才写该场景的技能（专业流程）；没有专属技能就写「—」，别硬造
```

- 步骤 ①②③④ 的顺序是**依赖顺序**：没有 json 就没有会话 id，没有会话 id 就没法绑定；
  没有定位卡，技能写得再好 AI 也不知道该不该用。
- **一个场景可以有两条会话**（例如"底层改造"和"界面改造"共用一张定位卡）——
  这时两行**共用同一张卡**，卡里用 `§一` / `§二` 分节，靠 `$env:DSH_SESSION_ID` 分左右（见下节）。

---

## 4. 开场 30 秒认领（每次新会话必做的四步）

```powershell
# ① 拿自己是谁（引擎给每条会话一个 id）
$env:DSH_SESSION_ID

# ② 在这个 id 上查表 → 得到 场景 / 定位卡 / 主技能 / 场景记忆
#    ③ 读定位卡（职责、资产、触发词、铁律、上次进度）
#    ④ 读场景记忆的 §〇 当前交接（进度 / 下一步 / 卡点）—— 这就是"上次干到哪"
```

四步做完再动手。**省这几分钟，能省掉几小时返工**（典型返工：干完才发现这不是本场景的地盘）。

---

## 5. 防串台：三个字段缺一不可

会话绑定的三个字段（名字很像，作用完全不同，细节见 [`../02-会话定位与跟随/二-会话绑定三字段.md`](../02-会话定位与跟随/二-会话绑定三字段.md)）：

| 字段 | 作用 | 张冠李戴的后果 |
|---|---|---|
| `sessionId` | **精确**指向一条会话（唯一权威） | 指到别的会话 ⇒ 你在替别人干活 |
| `sessionTitle` | 按**标题**找会话（人读的） | 标题重名 ⇒ 绑到错的那条 |
| `pinTarget` | 按**目标**找会话（数组，首项优先） | 顺序错 ⇒ 优先绑到旧会话 |

> **最少也要 ①②**：`sessionId` 定准，`pinTarget` 兜底。只有标题没有 id 是最脆的做法。

---

## 6. 换会话时（413 / 分叉 / 重开）必须同步三处

换会话不是"开个新窗口"，是**换掉一条会话的身份**。三处不同步，面板就会指向一条已经归档的会话：

```
① scenarios\<场景>.json        → sessionId / sessionTitle 改成新的
② 身份索引表（本篇这份）        → 会话 id 列改成新的
③ 场景记忆的 §〇 当前交接       → 写上"本交接由会话 <新id> 于 <日期> 改写"
```

跑完自检：`node <DSH根>\外壳\scripts\sessions.mjs --check` —— 应该逐面板打印"✓ id 命中（身份校验通过）"。

## 7. 空表模板（拷走就能填）

```markdown
# 场景身份索引 · <N> 个场景 / <M> 个 AI 面板 ↔ 会话 ↔ 定位卡

> **这是「我是谁」的唯一对照表。** 工作台每个场景都挂着常驻 AI 会话；
> 引擎不按场景注入任何东西 —— 所以开场认领身份只能靠这张表 + 定位卡。
> 数据源：`scenarios\*.json`（**以 json 为准**）｜ 最后更新：<日期>

## 一、怎么认领（开场第一件事）

1. 跑 `$env:DSH_SESSION_ID` 拿本次会话 id；
2. 在本表查它 → 得到 场景 / 定位卡 / 主技能 / 场景记忆；
3. 读定位卡（职责、资产地图、触发词、铁律、上次进度）；
4. 读场景记忆的 `§〇 当前交接`。**四步做完再动手。**

## 二、对照表

| 场景 id | 面板 id | 面板标题 | 会话名（`pinTarget` 首项） | 会话 id | 定位卡 | 主技能 |
|---|---|---|---|---|---|---|
| `<场景id>` | `<面板id>` | AI·`<中文名>` | `<会话名>` | `session-0000…` | `<DSH根>\外壳\scenarios\<场景>-context.md` | `<技能>` |

## 三、两个容易搞错的点

- **一个场景可以有两块面板/两条会话**：共用一张定位卡，靠 `$env:DSH_SESSION_ID` 分左右；
- **表与 json 不一致 = 表过期**：以 json 为准，改表不改 json 等于没改。

## 四、换会话时必须同步三处

`scenarios\<场景>.json` 的 `sessionId` / 本表的会话 id 列 / 场景记忆 `§〇` 的交接署名 ——
同步完跑 `node <DSH根>\外壳\scripts\sessions.mjs --check`。

## 五、写回点（干完活，新事实写到哪里）

| 场景 | 场景记忆（长期） | 项目级写回点 | 场景级（进度） | 技能（新坑） |
|---|---|---|---|---|
| `<场景id>` | `<DSH根>\引擎\场景项目信息\<场景>\项目信息.md` | `<项目目录>\项目信息.md` | `<定位卡>` | `<技能>` |
```

---

## 8. 三个坑（真踩过）

| 症状 | 根因 | 修法 |
|---|---|---|
| 切场景后 AI "失忆"，像换了个人 | `sessionId` 指到了旧会话/别条会话 | 查表改 id → 跑 `sessions.mjs --check` |
| 两个面板抢同一个会话 | 只写了 `sessionTitle`，两条会话还**重名** | 每条会话给唯一标题；`pinTarget` 首项要不同 |
| 表一直显示"身份校验通过"，但 AI 干错活 | 表对了、**定位卡过期**（职责写的是上一版） | 卡只是导航，判据以技能与场景记忆为准；卡要跟着改 |
