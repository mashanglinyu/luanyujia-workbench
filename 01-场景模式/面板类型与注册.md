# 面板类型与注册

> **面板 = 一个 `type` + 一块位置。** 场景 json 里只写 `type`，具体长什么样由**渲染器**决定 ——
> 所以「加一个新面板类型」= 注册一个渲染器，**不用动场景配置的结构**。

---

## 1. 渲染器就是一张表

界面里常驻一张**面板类型表**：键 = `type`，值 = 一个函数。

```js
renderers['hello'] = function (body, meta, head) {
  body.textContent = '你好，' + (meta.title || '面板');
};
```

渲染时按 `type` 查表：查到就调用，查不到就在面板里显示"未知面板类型: hello"。

**内置类型**（表里现成的成员，可直接在 json 里用）：

| 组 | 类型 |
|---|---|
| 文件与预览 | `file`（文件浏览）、`view`（文档/图片/视频预览）、`web`（内嵌网页）、`embed`（带独立登录态的网页） |
| 内容与流程 | `flow`（流程画布）、`log`（日志）、`reserved`（占位） |
| 容器 | `combo`（组合容器）、`shell`（子面板容器）、`dash`（仪表盘） |
| 数据展示 | `chart` / `board` / `screen` / `market`（行情与看板类） |
| 场景专属 | 各场景自己注册的，通常带前缀：`site-*`、`bl-*`、`review-*` … |
| AI | `harness`（内嵌 AI 对话面板 —— **这是本工作台给它的类型名**，见 [02](../02-会话定位与跟随/README.md)） |

> ⚠️ 这张表来自**一套真实跑着的工作台**：里面的名字（尤其 `harness` 这个名字）是那套实现的取值。
> 你自己搭的时候，**类型名随你定** —— 关键是"场景 json 里写什么、渲染器表里就注册什么"，两边对上即可。

> 想要全量清单：在渲染器文件里搜 `renderers.` 与 `renderers[` —— **表就是真身**，不用另外维护一份名单。

## 2. 渲染函数拿到的三个参数

| 参数 | 是什么 | 能拿它做什么 |
|---|---|---|
| `body` | 面板正文容器（`div.panel-body`，已带 `data-kind=<type>`） | 往里塞内容；用 `data-kind` 做样式钩子 |
| `meta` | 该面板的 json 对象（原样，外加宿主注入的 `scenario`） | 读 `title` / `sub` / 自定义字段 |
| `head` | 标题栏元素 | 加按钮、加状态字（标题与序号已由宿主放好） |

**返回值**：可以返回一个函数 —— 它会在**切场景 / 重建面板**时被调用，用来撤定时器、解绑监听。不返回也行，但异步内容必须收尾。

```js
renderers['clock'] = function (body, meta, head) {
  const line = document.createElement('div');
  body.appendChild(line);
  const tick = () => { line.textContent = new Date().toLocaleTimeString(); };
  tick();
  const timer = setInterval(tick, 1000);
  return function cleanup() { clearInterval(timer); };   // ★ 不收 = 切场景后还在后台跑
};
```

## 3. 从零加一个面板类型（照抄就能跑）

**① 在渲染器文件末尾追加一段：**

```js
// 我的第一个面板：一句话 + 一个按钮
renderers['hello'] = function (body, meta, head) {
  const line = document.createElement('div');
  line.textContent = meta.text || '还没写内容';
  body.appendChild(line);

  const btn = document.createElement('button');
  btn.textContent = '换一句';
  btn.onclick = function () {
    line.textContent = '现在时间：' + new Date().toLocaleTimeString();
  };
  head.appendChild(btn);        // 按钮挂到标题栏
};
```

**② 在场景 json 里用上它：**

```json
{
  "id": "demo-hello", "title": "打招呼", "type": "hello",
  "text": "你好", "col": 1, "row": 1, "w": 2, "h": 1
}
```

**③ 让改动生效**：走面板自刷新通道（见 [面板通用能力](面板通用能力.md) §2），**不需要重启程序**。

## 4. 五条经验（都是踩出来的）

1. **命名带场景前缀**：`file`、`view`、`web` 这类通用名早晚会撞车；自己的场景统一用 `xx-` 前缀（例：`site-preview`、`bl-live`）。
2. **不要依赖外网资源**：CDN 上的图标字体/脚本一旦加载不出来，界面上就是一个**空白框**（离线、内网、被墙都一样中招）→ 图标一律**内联 SVG**，字体用系统字体。
3. **异步内容自己管生命周期**：轮询、`setTimeout`、`webview` 事件，都在 cleanup 里收尾。
4. **面板是"一格"，不是"整页"**：宽度随窗口和版面变（经常只有 1/4 宽），布局用 `flex`/`grid` + `min-width: 0`，别写死像素宽。
5. **重量级内容才用 `<webview>`**：内嵌网页自带独立进程与登录态（分区）问题；只是展示内容，优先本地渲染。

---

## 5. 类型表放在哪、怎么热更

- 渲染器集中在一个（或少数几个）渲染层文件里，统一挂到一个**全局变量**上（例：`window.PANEL_RENDERERS = renderers`）；
- 界面按这个全局变量取表 —— 所以**改渲染器不用重启**，重载面板即可；
- **主进程 / 预加载**里的改动不在热更范围（新增 IPC 接口属于这一类，必须重启）。
