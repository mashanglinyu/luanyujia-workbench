# 面板类型总览 —— 这套壳里真实用过的 24 种面板

> [`面板类型与注册.md`](面板类型与注册.md) 讲的是「**怎么加**一种新面板」；
> 这一页补上另一半：**到底有哪些类型、各自解决什么问题**。
>
> 下面 24 种全来自一台真跑着的机器（配置见 [`../06-场景实例/`](../06-场景实例/)）。
> ⚠ 它们是**类型名**，不是能直接跑的代码：每种都要你在 `renderer/` 里注册一个渲染器（见文末六步）。

---

## 一、按家族看（24 种分 7 族）

### 1. 通用族（8 种）—— 90% 的场景只用这几个就够

| 类型 | 它显示什么 | 关键字段 | 一句话判据 |
|---|---|---|---|
| `view` | **预览/阅读器**：文件、图片、文档、网页都在这里看 | `home`（是否首页）、`homeFolders`（快捷文件夹）、`filesPanel`（配对的文件面板） | 需要"看内容"就用它 |
| `file` | **文件管理**：目录树 + 打开 | `mode`（local）、`drives`（显示哪些盘）、`viewPanel`（点开去哪预览） | 需要"找文件"就用它 |
| `embed` | **嵌一个网页**（带登录态，比如某站首页） | `url` | 只是"要看那个网站" |
| `web` | **内嵌浏览器/网址面板**（可导航、可刷新） | `url` / 起始页 | 需要在面板里**操作**网页 |
| `harness` | **AI 会话面板**（钉一条会话） | `sessionTitle` / `sessionId` / `pinTarget` / `expand` | 每个场景至少一块 |
| `reserved` | **预留占位**（画好格子但先留空） | `title` | 版式先定、功能后补 |
| `combo` | **组合容器**：一个面板里分几块 | 子块定义 | 一块地要放两样东西 |
| `dash` | **仪表盘容器**：KPI 卡片排一排 | 卡片定义 | 一眼看几个数字 |

> `view` + `file` 是**天然一对**：`file` 的 `viewPanel` 指向 `view` 的 id，点文件就在右边打开。
> 这个双面板组合是整套壳里复用率最高的搭配（工作台改造、设计杂活、视频工作流都用它）。

### 2. 流程图族（1 种）

| 类型 | 它显示什么 | 关键字段 |
|---|---|---|
| `flow` | **节点画布**：把工序摆成可点、可拖的节点图 | 节点/连线数据源（通常读写一个 JSON） |

> 这块是这套壳里最"重"的自定义面板（视频工作流用它把"素材→生成→剪辑"画成工单）。
> 加它之前先想清楚：**数据存哪、谁读写、怎么防止两个人同时改**。

### 3. 数据/行情族（3 种）

| 类型 | 它显示什么 |
|---|---|
| `chart` | 趋势图（时间序列） |
| `board` | 板块/分组雷达（多组横向对比） |
| `screen` | 筛选结果（一列候选 + 打标） |

> ⚠ 这一族的**数据敏感度最高**：面板配置里哪怕只留标题，也能反推出在看什么。
> 所以公开版本里这一族被整组清空了（见 [`../06-场景实例/`](../06-场景实例/) 的 `stock-analysis.json`）。

### 4. 电脑族（4 种）—— "本地电脑"场景专用

| 类型 | 它显示什么 |
|---|---|
| `pc-drives` | 各盘容量（按危险度变色） |
| `pc-toplarge` | 大户排行（哪个目录最占地方） |
| `pc-junk` | 可清理项（按类型分组） |
| `pc-ledger` | 清理台账（每次清了什么，只追加） |

> 这一族的价值不在"好看"，在于**把"该不该清"从口头判断变成看板数字**。

### 5. 站点族（4 种）—— "个人站点"场景专用

| 类型 | 它显示什么 |
|---|---|
| `site-preview` | 站点预览（带刷新，跳缓存） |
| `site-folder` | 源码目录树（只看几个固定夹） |
| `site-projects` | 项目清单（这个站里有哪些工程） |
| `site-urls` | 网址清单（线上地址 / 后台 / 文档） |

### 6. 复盘族（2 种）—— "自我复盘"场景专用

| 类型 | 它显示什么 |
|---|---|
| `review-doc` | 文档正文（档案类长文本，带目录） |
| `review-files` | 文件清单（按主题分组，点开即读） |

### 7. 三维族（2 种）—— "三维建模"场景专用

| 类型 | 它显示什么 |
|---|---|
| `bl-folder` | 工程资源夹（模型/贴图/输出） |
| `bl-live` | 外部软件实时连接（连上就显示状态与操作） |

## 二、三种最常用面板的"最小实现要点"

不贴完整代码（每个壳都不一样），只给**必须处理的那几点** —— 照这几条写，行为就不会歪。

### `harness`（AI 会话面板）

```
① 三字段绑定：sessionId（精确）+ sessionTitle（人读）+ pinTarget（兜底）
② ⛔ 两条会话用同一个场景时，名字**必须不同**（重名 = 串台）
③ 切场景时不要重建会话，只切"显示哪条"
④ 面板卸载要解绑监听，重载后不能叠加（幂等）
```

### `view` + `file`（预览 + 文件管理）

```
① file 面板点开文件 → 交给 view 面板（靠 viewPanel / filesPanel 互相指）
② view 面板要有 homeFolders：一打开就在有用的地方，别让人从盘根翻
③ 大文件只读前 N KB 预览，别整篇载入（否则一次点击卡住整个界面）
④ 路径不存在时**显示空态**，不要静默空白（否则你会以为面板坏了）
```

### `pc-drives`（容量）

```
① 数据源走系统调用（不要缓存太久，10 秒级刷新）
② 阈值分档上色（如 90% / 95%），⛔ 别只有一个数字
③ 点分区要能联动别的面板（点了 C 盘 → 大户排行切到 C）
```

## 三、加一种新面板：六步（与 [`面板类型与注册.md`](面板类型与注册.md) 对应）

```
① 起名：小写连字符（pc-drives / site-preview），一个词表达"它显示什么"
② 渲染器：renderer/renderers.js 里注册一个函数（约定：返回 DOM，不碰全局）
③ 配置：场景 json 的 panels 里写 { id, type, title, col, row, w, h }
④ 数据：想清楚数据从哪来（主进程 IPC / 读文件 / 系统调用），别在渲染层直接读盘
⑤ 空态与错误态：没数据时显示什么（这一步 90% 的人会漏）
⑥ 自检：切场景、⟳ 重载、拔掉数据源，三种情况各看一次
```

> **判据**：一个新面板如果"没数据时一片白、不报错"，它就不合格 ——
> 白屏是最难排查的故障，必须显式给空态。

## 四、这 24 种是怎么长出来的（给你参考的"生长顺序"）

```
第 1 天     view + file + harness        ← 能看文件、能跟 AI 聊
第 1 周     embed / web                  ← 能把常用网站搬进来
第 1 月     chart / board / screen       ← 第一个"业务图形"（最花时间）
第 2 月     pc-* 四件套                  ← 第一次"把判断变成数字"
第 3 月     flow                         ← 第一次"把工序变成画布"
之后        site-* / review-* / bl-*     ← 每个场景 2~4 个专用（按需，别预造）
```

**别一次造 24 个**。这套东西的经验是：**只有被真实使用逼出来的面板才活得久** ——
预造的面板通常用两次就没人点了。
