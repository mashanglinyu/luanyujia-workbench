# 面板通用能力

> 宿主已经替面板准备好的东西：标题栏、序号、展开、**自刷新通道**、与外壳通信的接口。
> 贯穿这一节的原则只有一条：**机器自己能做的事，不要交给人。**

---

## 1. 标题栏（宿主自动装配）

| 部件 | 从哪来 | 说明 |
|---|---|---|
| 序号徽标 `01` | 宿主 | 面板在场景 json 里的顺序（补零两位），方便口头指认"第 3 个窗口" |
| 标题 | 面板的 `title` | 面板名 |
| 小字 | 面板的 `sub` | 状态 / 路径，渲染器可随时更新 |
| **▲ 展开到最高** | AI 面板默认；其它类型写 `"expand": true` | 临时占满网格高度，再点收起 → [布局与网格](布局与网格.md) §5 |
| 自定义按钮 | 渲染器 | 渲染函数的第三个参数就是标题栏元素，`head.appendChild(...)` 即可 |

> 位置约定：序号在前、标题随后、按钮靠右。自定义按钮**追加到末尾**，别插到标题前面去抢位置。

## 2. 面板自刷新通道（改完界面自己生效）

这套工作台是**零构建**的：改完渲染器/样式，要面板重载才生效。为了让"改动 → 看到效果"**不需要人点一下**，宿主留了一条外部通道：

```
脚本写一个指令文件  →  主进程每 500ms 轮询到  →  重载匹配的面板  →  删掉指令文件
```

- 指令内容 = `all`（全部面板）或某个**场景 id**（只重载该场景的面板，按面板 URL 里的场景标识匹配）；
- 会话/脚本侧一条命令投递（脚本名以你自己的工作台为准，形如 `scripts/刷新面板.mjs [all|场景id]`）；
- **改完就自己投递一次、自己把效果摆出来**，别让用户去点刷新。

⚠️ 前提是**主进程已经加载了这条通道**（老版本读不到指令文件 ⇒ 表现是"投递了但界面没变化"，重启一次程序即长期有效）。
**主进程 / 预加载 / 新增插件行**这类改动不在热更范围，必须重启 —— 这时要一次说清"为什么必须重启 + 重启哪个 + 重启完我会做什么"。

## 3. 面板 ↔ 外壳：一切经过接口

面板（渲染层）拿不到系统能力，全部经由外壳暴露的接口，惯例长这样：

```js
await window.shell.file.read(path);      // 读文本文件
await window.shell.file.write(path, s);  // 写文本文件（注意盘符与大小限制）
await window.shell.app.openPath(path);   // 用系统默认程序打开
await window.shell.getScenario(id);      // 取场景配置
```

- 接口集中在**预加载层**（`window.<壳名>.*` —— 上面示例里这个壳名就叫 `shell`），主进程用 IPC 实现；
- **安全默认**：只开需要的口子 —— 打开路径前校验存在性、允许的协议（`http(s)/mailto`）、写文件限盘符与体积上限；
- **加接口 = 改预加载 + 主进程（要重启）**；**加面板 = 只改渲染器（不用重启）**。

## 4. 状态小字：把"我以为"变成"看得见"

面板最容易出的问题是**"看起来成功了其实没生效"**。对策：把关键状态写在标题行小字里，例如

- 当前绑定的对象（会话名 / 文件路径 / 连接目标）；
- 最近一次操作的结果与时间；
- 失败原因（一句话，不是错误码）。

这样用户不用开控制台就能判断"到底成没成"，排查时也有一处稳定的自检点（见 [04 · 工作台搭建](../04-工作台搭建/) 的「踩坑总表」）。

**推而广之**：凡是"我写了一个值，指望别的层去读"的地方，都要有一个**看得见的落点**（小字、截图、状态点）。写进去不等于生效。

## 5. 面板数据按场景分区

宿主组装面板时会往 `meta` 里注入 `scenario` 字段，面板用它给存储键加前缀：

```js
const key = 'my-panel:' + meta.scenario + ':' + meta.id;
```

**why**：同一个面板类型会被多个场景复用（一个文件面板可能出现在三个场景里），不带前缀就会互相覆盖。
同理，**AI 面板的浏览器分区也挂在面板 id 上**（见 [02 · 会话绑定三字段](../02-会话定位与跟随/二-会话绑定三字段.md) §4）。
