# 场景配置格式

> **一个场景 = 一份 JSON。** 这份 JSON 只回答三个问题：我叫什么、由哪几块面板拼成、每块摆在哪一格。
> 它**不写业务逻辑** —— 面板长什么样由渲染器决定（见 [面板类型与注册](面板类型与注册.md)）。
> 放进 `scenarios/` 目录即被自动发现：**不需要注册、不需要改主进程代码**。

> ⚠️ **本文示例是占位符，照抄不会跑**：`type` 必须换成你**已注册**的面板类型（写错只显示一行灰字，不报错），
> 面板 `id` 要带你自己的前缀，坐标要按你的版面调。新手先读 [新手必读](../新手必读.md)。

---

## 1. 最小可用示例

`scenarios/demo.json`：

```json
{
  "id": "demo",
  "name": "演示场景",
  "description": "三块面板：预览 + 文件 + 占位",

  "cols": 4,
  "panels": [
    { "id": "demo-preview", "title": "预览", "type": "view",     "col": 1, "row": 1, "w": 3, "h": 2 },
    { "id": "demo-files",   "title": "文件", "type": "file",     "col": 4, "row": 1, "w": 1, "h": 2 },
    { "id": "demo-slot",    "title": "预留", "type": "reserved", "col": 1, "row": 3, "w": 4, "h": 1 }
  ]
}
```

保存后切到该场景，就能看到三块面板。

> ⚠️ **文件名必须等于 `id`**：`id: "demo"` ↔ `scenarios/demo.json`。读取逻辑就是拿 id 去找同名文件，对不上等于"场景不存在"。

---

## 2. 顶层字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 场景唯一标识；**必须等于文件名**（`<id>.json`） |
| `name` | ✅ | 标签栏上显示的名字 |
| `description` | | 一句话说明（场景列表里用） |
| `panels` | ✅ | 面板数组；顺序 = 渲染顺序，也决定标题栏的序号徽标 `01`、`02`… |
| `cols` | | 网格列数，默认 `4`。想排"五分之三 / 五分之二"这类比例时才改 → [布局与网格](布局与网格.md) |
| `meta` | | **可选**：场景级元数据（该场景要连的服务、要读的路径清单、映射表…）。渲染层不解析，由该场景自己的面板按需取 |
| `theme` / `layout` | | **预留字段**：当前实现里不参与渲染（主题由界面上的全局开关控制，布局固定为网格）。写了不影响运行，别指望它换主题 |

---

## 3. 面板字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | ✅ | 面板唯一标识。**这是面板的持久化身份**：存储键、独立分区、状态记忆都挂在它上面 |
| `title` | ✅ | 标题栏文字 |
| `type` | ✅ | 渲染器名，决定这块面板长什么样；**没注册过就会显示"未知面板类型: xxx"** |
| `sub` | | 标题栏小字（状态 / 路径等），渲染器可随时更新 |
| `col` / `row` | | 起始格，列与行都**从 1 开始**；不写 = 交给自动排版 |
| `w` / `h` | | 跨几列 / 跨几行，默认 `2` / `2` |
| `expand` | | 非 AI 面板也想要"▲ 展开到最高"时写 `true`（AI 面板默认自带） |
| 自定义字段 | | 想给面板加配置项就**直接往面板对象里写**，渲染器从 `meta` 里读（例：`"text": "你好"`） |

**AI 面板**（本工作台给它的类型名是 `harness`；换成你自己的实现时，就写你自己的类型名）额外多三个字段 —— 它们是整个板块 02 的主题：

```json
{
  "id": "demo-ai",
  "title": "AI·演示",
  "type": "harness",
  "sessionTitle": "演示场景",
  "sessionId": "session-00000000-0000-0000-0000-000000000000",
  "pinTarget": ["演示场景", "演示"],
  "col": 2, "row": 3, "w": 3, "h": 2
}
```

→ 三个字段各管什么、少写一个会怎样：见 [02 · 会话绑定三字段](../02-会话定位与跟随/二-会话绑定三字段.md)。

## 4. 加载链路（出问题按这条链排查）

```
scenarios/<id>.json
   ↓ 主进程：扫 scenarios/ 目录（按文件名字典序）→ 列表 / 按 id 读单个
   ↓ 渲染层：拿到该场景的 json → 清空当前网格 → 逐个面板组装
   ↓ 每个面板：按 type 查渲染器表 → 渲染器拿到 (body, meta, head) 自己画
```

- **加场景 = 丢一份 json**：目录每次都重扫，不缓存列表；
- **切场景 = 整块重建**：旧面板返回的清理函数会被调用（定时器、监听器在这里撤）；
- **面板会被注入 `scenario` 字段**：面板由此知道自己属于哪个场景，数据按场景分区（见 [面板通用能力](面板通用能力.md) §5）。

---

## 5. 四条硬规矩

1. **文件名 = `id`**：读取逻辑就是 `scenarios/<id>.json`，名字对不上就是"场景不存在"。
2. **`type` 必须已注册**：没注册时面板里显示一行灰字，**不报错、也不崩** —— 别把"界面没变化"当成缓存问题。
3. **面板 `id` 是身份，不是标签**：它决定存储键与独立分区。**改 id = 换了一个面板**（绑定与状态全丢）。
4. **场景之间互不影响**：加一个场景不该动到已有场景，这是设计底线。要复用就复制整份 json，再改 `id` 与各面板 `id` 前缀。

---

## 6. 症状对照

| 症状 | 多半是 |
|---|---|
| 标签栏里没有这个场景 | 文件不在 `scenarios/`、不是 `.json`、或 JSON 语法错误（解析失败会被静默跳过） |
| 有场景，但面板写着"未知面板类型" | `type` 拼错，或渲染器没注册 |
| 有场景，但网格一片空白 | `panels` 为空数组；或坐标把面板推到了看不见的格子里 |
| 面板位置和想象的不一样 | 坐标只写了一半（写了 `col` 没写 `row`）→ 落进自动流，见 [布局与网格](布局与网格.md) |
| 改完 json 界面没反应 | 场景在**切场景**时才重建：切走再切回来（或重载界面） |
