# 用法与产物

> **这个文件干什么**：讲清楚「AI 调工具 → 产物落在哪 → 怎么再读回来」这条链路。
> 这是最容易出问题的一段：**很多人以为工具没跑成功，其实是产物放错地方 / 读不回来。**

---

## 一、一次工具调用的完整链路

```
你说话
  → AI 决定调工具（读文件 / 跑命令 / 搜网页）
  → 工具返回结果
      ├── 结果小（< 12k token）：直接回给模型
      └── 结果大：只回一个「存在这里了」的路径 + 摘要
  → AI 决定：直接用摘要 / 还是去读那个路径
```

**关键设计**：大输出不塞回上下文，只给路径。因为上下文是有限资源，而**文件是无限的**。

---

## 二、产物该放哪（三档，别乱放）

| 产物类型 | 放哪 | 例子 |
|---|---|---|
| 大体积 / 纯一次性 | `<工作区>\_临时\` | 视频、模型、下载的镜像、试跑输出 |
| 有点价值 / 要复核 | `<DSH根>\工作区\_临时\<会话名>-<时间>\` | 报告草稿、待复核的数据 |
| 核心 / 要长期留 | `<DSH根>\` 对应项目目录 | 工具本体、文档、素材、发布物 |

**⛔ 三条红线**

1. **不放 C 盘 `%TEMP%`** —— 关机就没，而且很多机器上 C 盘空间紧张。
2. **不放盘根 / 桌面** —— 三天就变成垃圾场。
3. **"临时"不等于"会自动清"** —— 没有任何工具保证替你收尾，**谁建的谁收**。

### 让机制替你判断落点

别在提示词里写死路径，让工具判断：

```bash
node <DSH根>\工具\临时路径.mjs --big    # 大体积 → 打印并建好目录
node <DSH根>\工具\临时路径.mjs --keep   # 要复核 → 打印并建好目录
node <DSH根>\工具\临时路径.mjs --check <路径>   # 检查某路径是否违规
```

合规检查可以挂进体检（有违规就 exit 1），这样**规矩就变成了机制**，不靠人记。

## 三、大输出怎么接回上下文

工具返回被截断时，会带一行 `stored at: <路径>`。正确做法：

```
1. 先读摘要，判断需不需要看全文
2. 需要 → 用 grep 先搜关键词，再按行号读那一段
3. 不需要 → 直接用摘要，别把整篇读进来
```

**反例**：拿到路径就 `read` 整个文件 —— 一个大文件能吃掉半个窗口，后面的活就没得干了。

## 四、工具结果里的三种"假成功"

| 现象 | 真因 | 怎么验 |
|---|---|---|
| 命令退出码 0，但网站没变 | 缓存 / 部署没生效 / 推到了别的分支 | **看 hash、看探活**，不看退出码 |
| 脚本打印"已发送" | 它只是把字打进了日志 | 必须有**回执或状态变化**才算成功 |
| 文件写入成功，但页面不更新 | 前端有本地缓存（`localStorage`） | 提升缓存版本号 / 强刷 |

> 一句话：**"程序说成功"不算成功，"外部事实变了"才算。**

## 五、跨 AI 协作时的消息格式

多个 AI 当同事时，消息要能被"机器读、人也能读"：

```
【需要回执】<要对方做什么>
  背景：<一句话>
  验收：<怎么算做完>
  期限：<可选>

【不需要回执·知悉】<结论>
  证据：<文件路径 / 命令输出 / 链接>
  落盘：<改了什么文件>
```

**四条硬规矩**

1. **要对方动手 → 必须叫醒**（只落盘不算派活）
2. **回执必须用投递工具发** —— 只在自己窗口说一句"我做完了"，发起方收不到 = 没闭环
3. **同一件事 ≤3 条消息**：派单 + 回执 + 收尾；收到"知悉"**一个字都不回**
4. **判据：活干完了但对方还不知道 = 没干完**

## 六、一个最容易被忽略的点

**产物路径要写进交付说明里。**

不管是给人还是给 AI，交付的时候都说清楚：

```
改了哪些文件
产物在哪（绝对路径）
怎么验证（命令 / 看到什么算成功）
怎么回滚
```

少了后两条，接手的人（或下一个 AI）就得从头猜 —— 这才是"交接"最容易丢的东西。
