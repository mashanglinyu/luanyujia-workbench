# 五 · GPU 优先机制 —— 哪些活该上 GPU，什么时候必须退回 CPU

> 动机很朴素：**能上 GPU 的活别用 CPU 硬扛**，但也**别以为 GPU 就一定快**。
>
> 这套机制的结论是：**只有三类活真的能用 GPU**，其余全是调远端 API ——
> 分不清这一点，会得到两种失败：白折腾（以为快了其实更慢），或者把机器打爆。

---

## 1. 唯一判据：只有三类活能上 GPU

| ✅ 能用 GPU | 为什么 | 典型实现 |
|---|---|---|
| **OCR**（文字识别） | 纯本地视觉推理，批量大 | onnxruntime + CUDA provider |
| **视频编码** | 硬件编码器是独立单元 | ffmpeg `h264_nvenc` / `hevc_nvenc` / `av1_nvenc` |
| **三维渲染** | 天生就是 GPU 活 | Blender Cycles / ComfyUI |

| ⛔ 用不上 GPU | 真相 |
|---|---|
| 大模型推理 / 对话 | 你调的是**远端 API**，本地 GPU 完全不参与 |
| "AI 生图"（云端服务） | 同上，远端算的 |
| 各类"加速一下"? | 先问：它到底在哪算？ |

> 判据一句话：**"这个活的数据是不是要在这台机器上算？"** 不是 ⇒ 别动 GPU 的心思。

---

## 2. 判据只写在一处（别在每个脚本里各判一次）

```
调用前问一句：shouldUseGpu(task)  ⇒  true / false
    true  ⇒ 走 GPU 路径
    false ⇒ 走 CPU 路径，并把 why 记下来
```

**为什么要集中**：同一个判断写在两个脚本里，就会出现"这个脚本认为该上 GPU、那个认为不该"，
然后两台机器/两个任务表现不一致 —— 而且没人能复现。

> ⛔ 如果判据工具拿不到（没装、路径变了、探测失败），**照 CPU 跑并记 why**，
> 而不是"因为 GPU 不可用所以任务失败"。**降级不是失败。**

---

## 3. 退 CPU 时不是"直接跑"，有三条硬约束

这是踩出来的（曾经 6 路并行 OCR 把 8 核机器打到假死）：

| 约束 | 值 | 为什么 |
|---|---|---|
| **进程数** | **单进程**（1 路） | 多路并行时每个进程都以为自己能用满 CPU |
| **线程数** | `OMP_NUM_THREADS=2`、`MKL_NUM_THREADS=2` | 不设的话底层库默认"看到几核开几核"，1 个进程就能吃满 |
| **优先级** | `BelowNormal` | 让用户还能正常用机器 |

> 判据：**"退 CPU"不等于"降级"，它是另一套参数** —— 不设这三条，退 CPU 比不跑更糟。

---

## 4. 验收：什么才算"真的用上 GPU 了"

⛔ **"能跑通"不算证据。** 必须三条同时具备：

```
① providers 列表里出现 CUDA（不是 CPUExecutionProvider 兜底）
② 有量化指标：秒/页（OCR）或 fps / 编码速度（视频）或 采样速度（渲染）
③ 显存占用有数字（进程确实占用了显存）
```

反例（很常见）：日志里写着 "CUDA available"，但实际跑在 CPU 上 —— 因为
provider 顺序不对、或 onnxruntime 装的是 CPU 版。**"available" ≠ "in use"**。

---

## 5. 负载闸：GPU 不等于可以无限并行

显存和 CPU 都是**共享资源**。同一台机器上可能同时有：

- 三维渲染在跑（ComfyUI / Blender 吃显存）
- 视频任务在出帧
- 一堆会话在等 API

所以派活前要看机器负载：

| 负载 | 允许做什么 |
|---|---|
| 任一资源 **≥90%** | ⛔ 不派子代理、不唤醒别的会话（只会一起变慢） |
| 任一资源 **≥95%** | ⛔ 连体检/构建/全盘扫描都别跑（它们也吃 IO/CPU） |
| 重活 | 降到 **≤3 路** 并行 + `BelowNormal` |

> 关键认知：**"我这一个任务很快"是局部判断；"机器现在能不能再接活"是全局判断。**
> 多 AI 系统里，后者才是决定体验的那个。

---

## 6. 失效模式

| 症状 | 根因 | 修法 |
|---|---|---|
| 上了 GPU 反而更慢 | 小批量作业，传输/启动开销 > 计算收益 | 批太小就别上 GPU；用秒/页对比后再定 |
| 日志说 CUDA，实际跑 CPU | provider 顺序/版本不对 | 验收看 ① providers ② 秒/页 ③ 显存，三条缺一不算 |
| 机器假死、风扇狂转 | 多进程 + 线程没限 | 单进程 + 线程≤2 + BelowNormal |
| 渲染/出帧时别的任务全卡 | 显存被抢，没人做全局判断 | 派前看负载闸；≥90% 不派 |
| 换台机器就崩 | 判据写死在脚本里 / 假设一定有 GPU | 判据集中在一处；拿不到就退 CPU 并记 why |

---

## 7. 最小可用（一条就够）

**先只做这一件**：把"这个活要不要上 GPU"的判断**收进一个函数**，
所有脚本都调它；拿不到结果就**照 CPU 跑并记 why**。

等你真的开始跑 OCR / 视频编码 / 三维渲染了，再补第 3 节的三条约束和验收三条。
