# 三 · 场景体系 —— 一个场景 = 一类会反复回来的活

> 这套工作台里最重要的一个概念是「**场景**」。它不是一个文件夹，也不是一个标签页 ——
> 它是**"一类活 + 一套资产 + 一套流程 + 一条常驻 AI"** 的打包。
>
> 学这套东西，学会"怎么切场景"，就等于学会了一半。

---

## 1. 先回答：为什么要切场景（一个窗口不行吗）

一个窗口也能用，但会依次撞上三堵墙：

| 撞墙 | 现象 | 原因 |
|---|---|---|
| 第一堵：**上下文互挤** | 你聊股票时，AI 还在想着刚才的设计稿 | 一个会话只有一条上下文，所有话题共享它 |
| 第二堵：**记忆互串** | "上次说改的那个"—— 它指的是哪个项目？ | 一份记忆记录多个项目 ⇒ 谁都不准 |
| 第三堵：**权限与规矩不分** | 清理的规矩套到了设计活上 | 规矩是跟着场景走的，混在一起就互相污染 |

**切场景的本质**：给每一类活一个**独立的上下文 + 独立的记忆 + 独立的规矩 + 独立的资产边界**。

---

## 2. 判据：什么时候该开一个场景

**开**：

- ✅ 这类活**会反复回来**（不是一次性）
- ✅ 有自己的**资产目录**（改完要写回同一份记忆）
- ✅ 有自己的**专业流程**（不是通用问答能解决的，需要专门技能）
- ✅ 有**明确的边界**（知道它不碰什么）

**不开**：

- ❌ 一次性的活（修个错别字、查个命令）→ 记进当次的项目笔记就好
- ❌ 只是"同一个大项目里的一个功能"→ 它属于现有场景的一个面板/子项
- ❌ 你自己都说不出它"不碰什么"→ 说明边界还没想清楚，先别开

**三个边角情况**（都有标准答案）：

| 情况 | 做法 |
|---|---|
| 一个场景里其实有**两套互不相关的活** | 一个场景 + **两条会话/两块 AI 面板**，共用一张卡、分节写职责（典型：底层改造 / 界面改造） |
| **客户/项目超过 3 个** | ⚠ 别一个客户一个场景 —— 改成"**一个场景 = 一类客户**"，客户之间用**项目档案**隔离 |
| 某个场景**长期没活** | 归档它（保留记忆与索引），别让它占着标签栏 |

> **一句话判据**：**"半年后我还会为它单独打开一个窗口吗？"** 答不上来就别开。

## 3. 六件套：一个场景由什么组成

这是整套体系里最值得抄的一张表。**缺任何一件，那个场景都会以某种方式失效**。

| # | 组件 | 是什么 | 缺了会怎样 |
|---|---|---|---|
| 1 | **场景配置** `<id>.json` | 面板布局、网格坐标、会话绑定 | 标签栏里根本不出现这个场景 |
| 2 | **定位卡** `<id>-context.md` | 职责 / 资产地图 / 触发词 / 铁律 / 上次进度 | AI 不知道自己该干什么、能碰什么 |
| 3 | **场景记忆** `项目信息.md` | `§〇 交接` + 长期决策与坑（见 [二-记忆机制](二-记忆机制.md)） | 换会话就断片 |
| 4 | **专属技能** `技能名/SKILL.md` | 这类活的专业流程（可执行的步骤与判据） | AI 用通用办法硬干专业活 |
| 5 | **专属面板**（可选） | 这类活需要的专用界面（如"容量雷达""画布"） | 只能靠聊天，效率低 |
| 6 | **常驻会话 + 身份索引一行** | 一条固定的 AI 会话 + 它在索引表里的那一行 | 引擎不注入身份 ⇒ AI 会猜，一猜就串台 |

> 前六件里，**2、3、6 是不可省的三件**（1、4、5 可以退化成"共用"）。
> 判断一个场景"成不成立"，就看这三件有没有：**卡（职责）、记忆（进度）、索引（身份）**。

## 4. 六件套的目录长什么样（空模板）

```
<你的工作台根>\
├── 外壳\
│   ├── scenarios\
│   │   ├── <场景id>.json              ← ① 场景配置
│   │   ├── <场景id>-context.md        ← ② 定位卡
│   │   └── _场景身份索引.md            ← ⑥ 身份索引（所有场景共用一张）
│   └── renderer\                      ← ⑤ 专属面板的渲染器（加面板类型时在这里注册）
├── 引擎\
│   ├── .dsh\skills\<技能名>\SKILL.md   ← ④ 专属技能
│   └── 场景项目信息\<场景>\项目信息.md  ← ③ 场景记忆（§〇 交接在这个文件开头）
└── <你自己的资产目录>\                 ← 这类活的项目文件（在哪都行，但要在定位卡里写清）
```

**每一件的"最小可运行版本"**：

| 组件 | 最小版本 | 说明 |
|---|---|---|
| ① 场景配置 | 只要有 `id / name / layout / cols / theme / panels` | `panels` 可以是空数组（一个空场景也能切过去） |
| ② 定位卡 | 只要四节：职责 / 资产 / 触发词 / 铁律 | 后续再补进度 |
| ③ 场景记忆 | 只要一个 `§〇` 五条 | 身份 / 进度 / 下一步 / 卡点 / 细节在哪 |
| ④ 技能 | 可以先写 10 行"流程骨架" | 没有就写「—」，⛔ 别硬造 |
| ⑤ 专属面板 | 可以先用通用面板（文件/网页/AI） | 没有专用面板不影响场景成立 |
| ⑥ 身份索引 | 一行七列（见 [05/四](../05-协作与规矩/四-身份索引-怎么建.md)） | 这一列是**唯一权威**：面板 ↔ 会话 |

> [`../模板/项目信息-模板.md`](../模板/项目信息-模板.md) ·

## 5. 身份：引擎**不会**告诉你"你是哪个场景"

这是最容易踩的坑，也是场景体系能成立的关键前提：

> **引擎不按场景注入任何东西。** 会话打开时，它并不知道自己是"哪个场景"。

所以"认领身份"必须是**开场 30 秒的固定动作**：

```
① 拿自己的会话 id（引擎给每条会话一个）
② 在身份索引表里查这个 id  →  得到：场景 / 定位卡 / 主技能 / 场景记忆
③ 读定位卡（职责 / 资产 / 触发词 / 铁律 / 上次进度）
④ 读场景记忆的 §〇（进度 / 下一步 / 卡点）
        ↓
     四步做完再动手
```

**为什么不能靠"在开场消息里写你是 XX 场景"**：
能用，但换会话/分叉时容易漏，而且面板那边改了它不知道。
**表是数据、卡是职责，两者都不在会话里** ⇒ 换多少次会话都还在。

> 详细做法（七列怎么填、防串台三字段、换会话同步三处）：
> [`../05-协作与规矩/四-身份索引-怎么建.md`](../05-协作与规矩/四-身份索引-怎么建.md) 与
> [`../02-会话定位与跟随/`](../02-会话定位与跟随/)。

## 6. 一个真实的切法（10 个场景，就是在这套工作台上跑着的）

下面这张表**没有任何个人信息**（名字、路径、客户、id 全部去掉），但它就是真实的切分结果 ——
你可以直接看出"一个场景 = 一类活"是怎么落地的：

| 场景 | 这类活是什么 | 为什么**必须**独立 | 六件套里的重头 |
|---|---|---|---|
| 工作台改造 | 改壳 / 改引擎 | 它动的是**别人的地基**，权限最高、风险最高 | 两条会话（底层 / 界面）+ 一张卡分节 |
| 客户系统运维 | 一个客户系统的部署、发布、排障 | 有**保密责任**，绝不能和别的项目混 | 定位卡 + 项目档案 + 专属技能 |
| 个人站点 | 自己的网站：改版、发布、内容 | 改完就要发布，发布有**公网风险** | 专用面板（预览/源码/网址）+ 发布链路 |
| 行情分析 | 看盘、复盘 | **数据敏感**（偏好即隐私）+ 面板类型最复杂 | 4 个自定义面板 + 空场景模板 |
| 视频工作流 | 素材 → 生成 → 剪辑 → 导出 | 流水线长，**中间产物巨大** | 画布面板 + 两条技能 |
| 三维建模 | 建模 / 材质 / 渲染 | 需要**连外部软件**（MCP），流程完全不同 | 面板要连本体 + 固定在最前 |
| 设计杂活 | 图标 / 配图 / 改尺寸 | **所有场景都会找它**，是"唯一对口" | 预览面板 + 请求协议 |
| 本地电脑 | 清理 / 容量 / 体检 | **全机唯一对口**，别人不许自己删 | 5 个自定义面板（容量/大户/可清/台账） |
| 自我复盘 | 个人档案 / 知识库 | **机主私人资料**，和软件资产严格分开 | 文档+文件面板 + 分级记忆 |
| B站视频理解 | 看视频 / 总结 | 有**专门工具链**（转写+视觉理解） | 嵌网页 + AI 双栏 |

> 📁 这 10 个场景的**真实配置**（已脱敏，面板坐标/类型/绑定全在）：
> [`../06-场景实例/`](../06-场景实例/) —— 想知道"配起来长什么样"，看那里比看这张表快。

**从这张表能看出的三条切分逻辑**（比"按项目切"更稳定）：

1. **按"风险/权限"切**：能改地基的（工作台改造）、能碰客户数据的（客户运维）、能删东西的（本地电脑）—— 必须独立，因为它们的权限不一样；
2. **按"资产性质"切**：要发布到公网的（站点）、私人的（复盘）、巨量中间产物的（视频）—— 因为它们对环境和存储的要求不一样；
3. **按"对口关系"切**：所有场景都会找它、且只能它做的（设计 / 清理）—— 因为"唯一对口"必须先有"一个"。

## 7. 场景之间怎么相处

场景不是孤岛。三件事必须提前定：

| 要定什么 | 去哪定 | 一句话 |
|---|---|---|
| **地盘**：每个场景能碰什么、不碰什么 | 各场景的定位卡 + 一张职能表 | 不写下来 = 每天都要吵一次 |
| **重叠**：同一件事两个场景都能干 | 一张**判据表** | 判据：资产归谁 / 唯一对口归谁 |
| **沟通**：怎么互相找 | 协作机制（派单/回执） | 见 [`一-协作机制.md`](一-协作机制.md) 第 4~6 节 |

**最有用的一条**：把"**唯一对口**"写进那个场景的地盘说明里。
例：「所有清理活归本地电脑场景，别的场景⛔不许自己删东西，只能发清理请求」——
一条这样的规矩，能消掉 80% 的越界。

## 8. 常见错误

| 错误 | 为什么会犯 | 后果 | 改法 |
|---|---|---|---|
| **一个场景管三个客户** | 图省事 | 记忆互串、保密边界糊掉 | 一个场景 = 一类客户，客户之间用项目档案隔离 |
| **场景名用项目名** | 直觉 | 项目改名/结束时场景名就废了 | 用"**这类活**"命名（如"客户系统运维"），不用具体项目名 |
| **只有 json，没有卡和记忆** | 以为配置就是场景 | AI 不知道自己该干什么 | 六件套至少补齐 ②③⑥ |
| **开了场景但没绑会话** | 忘了三字段 | 切过去一片空白，或显示别人那条 | 见 02 的三字段 |
| **把"一次性活"也开成场景** | 贪心 | 标签栏越来越长，每个都半死 | 定期归档长期没活的场景 |
| **两块 AI 面板重名** | 没注意 | **串台**（点左面板，干的是右面板的活） | 两条会话必须不同名；`pinTarget` 首项不能相同 |

## 9. 最小可用（先只做这一件）

**别一次开 10 个。** 从**一个**开始：

```
选一类你最常干的活
   ↓
开一个场景（json 里 panels 先放一个 AI 面板）
   ↓
写三份东西：定位卡（四节）· 场景记忆（§〇 五条）· 身份索引一行
   ↓
用两周 —— 你会发现"它该知道什么、不该碰什么"
   ↓
再补技能与专属面板；然后才考虑开第二个场景
```

> 判据：**"这个场景的 `§〇 交接`，我能在 30 秒内写完吗？"**
> 写不完说明它管的事太多，该拆了。
