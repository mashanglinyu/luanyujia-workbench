# 六 · 场景即人的一面（Scene Persona）

> 这一篇讲一件比「怎么分工」更软、但同样要落成机制的事：**同一个机主，在不同场景里是不同的人**。
> 我们把它写进系统，而不是靠 AI 猜。

---

## 1. 一个被忽略的事实

同一个机主，在 OA 运维那里语气是**急、烦、事多**；在个人站这边是**松、随手、句子短**；在复盘那里又**认真、愿意说细**。

这不是「心情」，是**场景决定了他以哪一面出现**——活的性质不同、压力不同、要的结果不同。

> 所以：**一个场景 = 一类活 + 一种相处方式。** 只做前半句，AI 就会用一套腔调应对所有事。

## 2. 结构：五个字段，一张表

每个场景在共享层维护**自己那一行**：

| 字段 | 定义（写什么） |
|---|---|
| 场景 | 场景名 / 面板 |
| 常见语气 | 急 / 稳 / 短 / 啰嗦 / 玩笑 / 公事公办（只写表达方式） |
| 典型原话 | **带日期与出处地照抄一句**；无出处即删。⛔ 本仓库不含任何真实原话（见 §4） |
| 雷区 | 这个场景里最招他烦的事（只写「什么会踩到」，不写「他为什么」） |
| 应对 | 这个场景该怎么回（长度 / 顺序 / 先给什么） |

**为什么原话要带日期与出处**：没有出处的"原话"最容易被 AI 顺手编出来——编出来的东西看着像、用起来错，而且无法复核。

## 3. 怎么用：开场读自己那行

每个场景开工前，先读**自己那一行**，决定三件事：

1. **回多长**：句子短的人，你一屏三段他就不看
2. **先说啥**：结果是数字/结论，还是过程/解释
3. **别踩什么**：雷区一行，比十条通用礼貌规则有用

> 这不是「伺候人」，是**减少来回**：说对一次，比说错三次再道歉便宜。

## 4. 四条硬边界（2026-11-04 定稿）

1. **只记表达方式，禁止从口气推原因**：「他这样说」可以记，「他为什么生气」不记
2. **一个场景是一个面，不是一个人**：禁止写「他是什么样的人」；表里的「急」只对 OA 运维这个场景
3. **原话必须带日期与出处，无出处即删**
4. **禁区**：健康 / 家庭 / 财务 / 证件 / 宗教；**且不做跨场景拼图**（别把 A 场景的只言片语拼成"他这个人"）

> 还有两条配套：**只改自己那行**（不替别人写）；**这张表不进主画像**（画像放恒定偏好，这里放分场景表达）。

## 5. 为什么值得写进机制（而不是记在心里）

- **AI 会换人**：会话重开、换模型、换场景，靠"记得"的偏好一定丢
- **人会变**：不同时期的语气不一样，表要能**追加**而不是覆盖（同一场景可以有多行，按日期排）
- **能验收**：写下来才能问"这个场景这条应对对不对"，不写就只能凭感觉

## 6. 和其他机制的关系

| 机制 | 管什么 | 和本文的分工 |
|---|---|---|
| 记忆机制（§二） | 事实、决策、项目进度 | 记「发生了什么」 |
| 场景体系（§三） | 一个场景怎么切、六件套 | 记「这个场景负责什么」 |
| **场景即人的一面（本篇）** | 同一个人的不同侧面 | 记「在这个场景里，他通常怎么说话」 |

> 三套合起来才是「一个立体的机主」：**做过什么 + 负责什么 + 以什么面目出现。**

---

⛔ 本机具体内容（真实原话、雷区、应对）只存共享层，**不随仓库公开**；这一页只讲结构与边界。
