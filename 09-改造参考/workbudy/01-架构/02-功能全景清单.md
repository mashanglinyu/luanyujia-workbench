**三个值得注意的工具**：

1. **`Monitor`** —— 长驻监控。不是"跑一条命令拿结果"，是"起一个监视器持续观察"。运维场景（等部署、盯日志）这是刚需，但它不常用，很多人不知道 Agent 能做这个。
2. **`Workflow`** —— 工作流。把多步流程定义成文件执行，不是每次靠模型现场编排。
3. **`REPL`** —— 把工具变成沙箱里的函数，模型写程序批量调。20 次调用从 20 次往返变 1 次。

```

**`memorySelector` 这个设计值得单独说**：记忆不是"全部塞进去"，而是有一个专门的 agent 负责**从记忆库里挑出这次相关的**。这是记忆系统的第三层——写入、存储、**检索**。你现在的方案只有前两层。

## 三、9 个斜杠命令

```
/init              为项目生成说明文件
/compact /_compact 手动压缩
/upgrade           升级
/statusline        配置状态栏
/security-review   安全审查
/commit            提交
/commit-push-pr    提交 + 推送 + 开 PR
/insights          使用洞察报告
```

**`/insights` 是个被低估的设计**：它分析你的历史使用记录，生成一份报告——你的高效工作流是什么、哪里卡住了、建议往项目说明里加什么。等于让产品自己诊断"用户用得怎么样"。

## 四、5 种输出风格

```

**输出风格独立于交互模式**——模式管"能做什么"，风格管"怎么说"。你现在只有一种说话方式。

## 五、38 个关闭的开关，比开启的更有信息量

它做了但没开的东西：

| 关闭项 | 含义 | 说明什么 |
|---|---|---|
| `SkillManage` | 技能自我管理 | **连它也没做到"AI 自己沉淀技能"**（印证之前的判断） |
| `FileDiffHistory` | 文件 diff 历史链 | 结果区能看变更，但**不保留完整 diff 链**，用的是快照 |
| `SandboxFileVersionManagement` | 沙箱文件版本管理 | 版本化被放弃，只做单次快照 |
| `AutoMode` | 自动选模型 | 模型表里有 `auto`，但功能关着 |
| `AudioTranscribe` | 语音转写 | 有工具，没开 |
| `ImageEdit` | 图像编辑 | 只能生成，不能改 |
| `CalendarMcp` | 日历接入 | 不做日程 |
| `PoiMap` | 地图 | 不做位置 |
| `ChannelSlack` / `ChannelTelegram` / `ChannelDiscord` | 三个海外 IM | 只留微信 / 企微 |
| `DisableCheckin` = false | —— | 签到是**开着**的（积分体系的核心留存手段） |
| `DisablePublishedApps` | —— | 发布应用是**开着**的 |

**两个结论**：

1. **它把资源全押在中国场景**：微信、企微、腾讯文档、腾讯乐享、ima、微云、微信支付，同时把 Slack/Discord/Telegram/日历/地图全部关掉。这不是技术取舍，是市场取舍。
2. **"变更 diff" 它自己也没做完整**。上一份档案里我标【推断】的那块，现在有了旁证：`FileDiffHistory` 和 `SandboxFileVersionManagement` 都是关的。所以你在 DSH 里做完整的「快照 → diff → 回滚」链，是能超过它的地方。

## 八、给 DSH 的取舍参考

**该抄的**：
1. `Monitor`（长驻监控）—— 你的运维场景刚需，你现在只能"跑一条命令等结果"
2. `memorySelector`（记忆检索层）—— 你缺的第三层
3. 输出风格 × 交互模式的正交设计
4. `/insights` 式的自我诊断

**可以超过它的**：
1. 完整 diff 链（它关着）
2. 技能自沉淀（`SkillManage` 它关着）
3. 发布链路 —— 你的家长端/教师端是它的"分享链接"替代不了的

**不该抄的**：
1. 五类知识库 —— 你只需要一种（本地 markdown）
2. IM 渠道 —— 你用不到
3. 插件市场 —— 是分发机制不是能力
