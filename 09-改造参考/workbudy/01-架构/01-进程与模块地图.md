# 进程与模块地图

## 一、进程模型（【实证】来自 asar 内 main/ 文件名 + 打包结构）

WorkBuddy 不是"一个 Electron 窗口里跑 Agent"。它是**三层**：

```
┌─────────────────────────────────────────────────────────┐
│ Renderer（Chromium）                                     │
│   app.asar / renderer/  + assets/                        │
│   纯 UI：对话、结果区、侧边栏、面板                       │
└──────────────────┬──────────────────────────────────────┘
                   │ preload/index.js (239KB) + bridge.js
┌──────────────────▼──────────────────────────────────────┐
│ Electron Main（宿主）                                    │
│   daemon-bootstrap.js (699KB)  ← 启动协调器               │
│   daemon-app-server-main.js (170KB) ← 本地 HTTP 服务      │
│   acp.js (99KB)  ← ACP 协议客户端                        │
│   browser-preview / app-server-mcp-apps-host / 更新服务   │
└──────────────────┬──────────────────────────────────────┘
                   │ ACP（Agent Client Protocol）
┌──────────────────▼──────────────────────────────────────┐
│ CLI Daemon（真正的 Agent）                                │
│   cli/dist/codebuddy-lite-wb.mjs + lazy chunks           │
│   工具、Hook、技能、MCP、记忆、子代理全在这一层            │
└─────────────────────────────────────────────────────────┘
```

**为什么要拆三层【推断】**：
1. Agent 进程崩了不带走 UI（`no-orphans.cjs`、`windows-job.cjs` 说明他们认真处理过孤儿进程）
2. CLI 可以脱离 GUI 单跑（`cli/bin/codebuddy` 是可执行入口），同一套内核喂给桌面端 / CLI / 服务端
3. daemon 预热池（`cli-prewarm-pool.js`，24KB）——会话开之前进程已经起来了，首字延迟靠这个压

**对 DSH 的启示**：你现在是 AI 面板和主进程耦合在一起。真要改，最低成本的做法不是重写，而是**把"跑 Agent"抽成一个独立子进程 + 一条 stdin/stdout JSON 协议**，面板只负责渲染事件流。这一步做完，后面所有功能（并行、断线重连、崩溃恢复）才有地方挂。

## 二、主进程模块边界（【实证】153 个语义模块名）

这些文件名本身就是一份架构说明书，按职责归类：

| 职责 | 模块 |
|---|---|
| 启动/生命周期 | `main-bootstrap` `daemon-bootstrap` `app-instance` `app-lifetime-job` `bootstrap-daemon-in-main-process` `core-process-roles` |
| 协议/桥接 | `acp` `bridge` `transport` `transport-error` `remote-window-broker-transport` `contract` `protocol` `host` |
| 本地服务 | `daemon-app-server-main` `app-server-*` `runtime-http` `runtime-handlers` `http` `server` `multipart-parser` |
| 会话/账号 | `account` `workbuddy-auth-product-coordinator` `legacy-auth-session-migrator` `credential-protection-bootstrap` `server-side-access-token` |
| 产物 | `archive-artifact-sweep` ★ `app-server-mcp-apps-host` `browser-preview` `office-window-host` |
| 性能/可观测 | `perf-metrics` `perf-profiler-handlers` `perf-menu-state-sync` `prompt-trace-reporter` `crash-reporter` `logger` `persistent-log-writer` |
| 更新 | `update-service` `update-service.win3` `update-timing-writer` |
| IM 接入 | `feishu` `dingtalk` `slack` `discord` `telegram` `qq` `weixin` `wecom-*` `wechatmp` `yuanbao` |
| 环境/路径 | `workbuddy-paths` `workbuddy-product-config` `env-product-provider` `dev-env-actions` |

三个值得单独拎出来的：

**`archive-artifact-sweep.js`（37KB）** —— 产物归档清理。产物目录会无限膨胀，它有独立的清扫器。DSH 如果要做"结果区"，这个必须一起做，否则半年后磁盘炸。

**`app-server-mcp-apps-host.js`（83KB）** —— MCP Apps 宿主。让 MCP server 能返回**可交互 UI**（不只是文本）。这是 WorkBuddy 的 `show_widget` / 富卡片能工作的底层。DSH 短期不用碰，但知道它存在。

**`prompt-trace-reporter.js`** —— 把"这一轮到底给模型喂了什么"上报。调提示词没有这个就是瞎调。

## 三、Agent 运行时的内部结构（【实证】来自 mjs 里的类名与日志前缀）

`codebuddy-lite-wb.mjs` 是 rspack 打的单文件，但类名和日志前缀没被抹掉，能反推出分层：

```
ToolManager           工具注册表 + 调用编排（日志前缀 [ToolManager]）
ToolHookManager       工具级 Hook 执行器（executePreToolUseHooks）
Session / SessionStore 会话状态、history、权限快照（toolPermissionDecisionSnapshots）
AgentTask / subAgentSession  子任务与子会话
PermissionService     needsApproval / permissionDecision
McpClientManager      MCP 连接与工具发现
SkillRegistry         技能索引（name + description 常驻）
MemoryService         三层记忆
CompactionService     上下文压缩（compact / microcompact）
```

**被压缩掉但有迹可循的关键机制**：

- `toolCallLoopGuard.checkBeforeExecute()` —— 防死循环。同一工具同一参数连续调用会被判 `stop`。
- `session.preToolUseHookResults` —— Hook 结果按 `callId` 缓存，判过一次不重复判（因为 hook 可能很贵）。
- `authorizeMcpEgress` / `authorizeMcpFinalAction` —— MCP 调用做了**两级**授权：出站前一次、最终动作前一次。第二级能看到 PreToolUse hook 改过的参数（`modifiedInput`），防"hook 放行原始参数、模型换参数再调"。
- `DeferExecuteTool` + `defer_loading` —— 工具默认**延迟加载**，schema 不进初始上下文，靠 `ToolSearch` 现查。这是他们工具数量能堆到上百还不爆上下文的原因。

## 四、DSH 该抄哪一层

| 层 | 现在 | 建议 |
|---|---|---|
| 进程模型 | 单体 | ② 优先级：抽 Agent 子进程。但可以晚做 |
| 主进程模块 | 未拆 | 不用照抄这么多，但 `artifact-sweep` / `prompt-trace` 两个思路要有 |
| 运行时分片 | 无 | **① 立刻抄**：工具延迟加载 + 分包。你现在工具一多就卡上下文 |
| UI | 多面板同屏（强） | 保留，只补"结果区" |
