### 机制摘要（≤150 字）

审批不是"要不要问"，而是 `(策略 × 权限档 × 逐路径可写性)` 算出的三值函数：能自动就自动、策略禁止升级就**直接拒**、其余问人。问人的结果进**按路径**的会话级缓存，多文件 patch 必须所有路径都批过才免问；无应答/超时按 `Denied` 处理（默认值就是拒绝）。

### 可抄到 DSH 的哪一块

`引擎\packages\fs\tool-fs\src\apply-patch.ts:153-159` 现在是：
```ts
const risky = patches.length > 3 || patches.some((p) => sensitive.test(p.path))
if (risky && args.confirm !== true) throw new Error('apply_patch needs confirmation: …')
```
`confirm` 是**模型自己填的**，等于自己给自己签字。而引擎里已有正确的闸：`packages\interaction\user-approval\src\index.ts:206+` `ApprovalService.request()`，**无 answerer 返回 `'unavailable'`（fail closed）**，且成对写 `approval/asked` + `approval/decided`。

### 最小实现（≤1 天）

1. 把 `risky` 换成 `decide(): 'auto' | 'ask' | 'reject'`：
   - `auto`：全部路径落在允许写根（复用现有 `sandbox.resolvePolicy('edit', …)`）
   - `reject`：`DSH_APPROVAL_APPLY_PATCH=never` 且不可 auto
   - `ask`：其余
2. `ask` 走 `ctx.get('approval').request({agent, toolName:'apply_patch', callId, reason})`；非 `'allowed-once'` 一律抛错。
3. **路径级缓存**：`外壳\data\approval-cache.json` = `{sessionId: {paths: {…: "approved-once"}}}`，命中条件 = patch 里**每个**路径都标过（照 codex 的 `all()`），命中则降到 `auto`。缓存随会话结束作废。
4. `DSH_APPROVAL_APPLY_PATCH=off|ask|never`（默认 `ask`）；`off` 完全回到今天的 `confirm` 行为（headless 逃生阀）。`confirm` 参数只在此模式下有效。
5. （可延后）`Granular` 的等价物：把 `sandbox_approval=false` 做成 `never` 档，即"不许升级到问人"，只能拒。

### 判据

```bash

node -e "…" # 会话里应出现 approval/asked + approval/decided 成对事件
# 2 无 answerer：把 answerer 摘掉（headless 启动）跑同一 patch
#   期望：不执行、报 [approval] unavailable；而不是静默通过
# 3 缓存：同目录同 4 文件再改一次
#   期望：无新的 approval/* 事件，patch 直接应用
# 4 回归：DSH_APPROVAL_APPLY_PATCH=off + confirm:true
#   期望：无 approval/* 事件，行为与今天一致
```
一条反向判据（防"假绿"）：**新增路径必须重新问** —— 在上述 patch 里加第 5 个文件（在 `启动器\`），缓存不命中 ⇒ 必须再出 `approval/asked`。

### 风险 / 不适用点

- **UI 没有 answerer ⇒ 功能等于关死**。codex 把 `TimedOut` 映射成 `Decline` 是合理的（它有 app-server）；DSH 若 `main.js` 没渲染 `approval/asked`，用户只会看到"失败"。所以顺序必须是：先 `off` 开关 → 再接 UI → 再默认 `ask`。
- 缓存键放"路径"比放"patch 内容"更实用，但会让"同一路径的**更危险**改动"免问。codex 用 `environment_id`（环境）压这个风险；DSH 可用"会话内 + 每次新 turn 失效"近似。
- 不抄它的 `Granular` 全量字段（`skill_approval`/`request_permissions`/MCP elicitation），DSH 没有这些入口。

### 最小实现（≤2 小时，纯 SQL/状态机，不动 schema 结构）

2. **收口 accepted**：`accepted` 只由 `finish()`（`:256-265`，前置 `status='delivered'`）产生。`回执哨兵.mjs:228-241` 继续写 `ack`（销账用），但不再影响 status。

   - `:269` 不再 `attempt+1`（`claim` 已经计过），只读；
   - 事件写成 `event(db, id, 'timeout', 'sweeper', {reason:'lease_expired', lease_until, attempt})`，而不是复用 `'expire'`；

## 7. 明确"不抄"的 2 条
