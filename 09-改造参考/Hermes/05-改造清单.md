# 05 改造清单

排序依据：**DSH 已知缺口 × 单条可独立落地 × 失败代价可逆**。字母是"该不该做"，数字是"先做哪条"。

- **A** = 缺口明确、单点可落地、失败可回滚 → 立刻做
- **B** = 缺口明确但要动主干/有回归面 → 排期做
- **C** = 收益真实但依赖前序或成本偏高 → 观察
- **D** = 不建议照抄（要么是 Hermes 的历史包袱，要么与 DSH 架构冲突）

> 合计 **44 条**：A 20 / B 13 / C 5 / D 6，与 `交接卡.json` 的 44 张卡一一对应。

**共同点**：全部 ≤300 行，全部是"纯函数 + 一个调用点"，全都不改 IPC/存储格式。这是第一批。

`ENV-01` 是补的：DSH 任务书里点名"**场景间消息无强制字段**"，前 21 条没有一条覆盖它。它的依据不在 Hermes 的 IPC 里（Hermes 没有多面板），而在跨网关投递契约 `HostedMemberDispatch`——把 17 字段降维成 7 字段的 `PanelEnvelope`，详见 `08-附录/A4`。

`INJ-03` 也是补的，而且是**实测逼出来的**：把 `threat_patterns.py` 的 36 条模式原样拿到 100 条中文攻击上跑，context 档只命中 9 条，其中 7 条靠不可见字符或内容里残留的英文，2 条靠 `curl`/`wget` 命令——**72 条纯中文语义攻击，0 命中**。补 8 条中文模式后 context 29% / strict 39%，误报 0 / 1。完整数据见 `08-附录/A9`，可直接用的正则在 `03-契约/cn-injection-patterns.json`。

**这条也顺带证实了 INJ-01 的"无 fast-path"不是加分项而是唯一防线**：36 条模式里**没有任何一条**匹配 `<untrusted_tool_result>`，围栏标签的伪造只能靠"上传内容的 `<` 一律换成 `‹`"来防。

`INJ-04` 是**用真实语料量出来的**，不是想出来的：拿 74 份用户本机真实中文文档（439,619 字符）跑，8 条中文模式 **0 命中**，但有 **12 份**命中 `invisible_unicode_U+FEFF`——逐字节一查，全部是 UTF-8 BOM。Hermes 的 `read_file` 链路会剥 BOM 所以查不出来，但 `terminal`（`cat`/`Get-Content`）、MCP 返回、子代理返回三条链路不剥，误报真实存在。修法两行、修后复测 **0/74**。详见 `08-附录/A12`。

`REC-01` / `REC-02` 是第 14 面补的，理由是它俩属于**最便宜的止损**：DSH 现在 429 之后立刻重试，等于在限流窗口内反复敲门——1 分钟的窗口能拖成 10 分钟。两条加起来约 200 行纯函数、无状态、不改任何存储格式，却能立刻消掉「越重试越不可用」这个正反馈。`REC-01` 的核心不是"多写几个 if"，而是**先承认状态码不够用**：同一个 403 在 Hermes 里分出四种含义（auth / billing / WAF / 内容策略），四种的恢复动作互斥。详见 `02-主线/14`，可跑实现在 `04-参考实现/retry-backoff.mjs`（79 项自测）。

`VER-01` / `VER-02` / `VER-05` 是第 15 面补的，它们解决的是前 14 面**一次都没定义过**的东西：**Agent 说"我做完了"，凭什么信**。

三条都属于"不新增实体、只加一条判断"的类型，但顺序不能乱：

- `VER-01` 是地基。它是整个验证层的唯一前提——`npm test | head -20` 的退出码属于 `head`（永远是 0），`npm test || true` 被抹成 0，`npm test &` 立刻返回 0 而测试还在跑。**不做这一条，后面任何"证据"都是假的**：台账会记下"进程启动成功"，然后更自信地放行。
- `VER-02` 是范围。`pytest tests/a.py` 是 targeted，`pytest` 是 full；前者不能产生"全部通过"的说法。缺这一维，Agent 改 5 个文件只测 1 个也能说全过。
- `VER-05` 决定这个功能能不能活过一周。改一次 README 就要求跑测试，用户第三天就会关掉它；而闸门只堵不疏时，模型的最优策略变成**编一个通过结果**——那比不验证更坏，因为它现在有"证据"。

三条合计约 150 行，全是纯函数。可跑实现在 `04-参考实现/verify-ledger.mjs`（55 项自测，含 11 行退出码真值表）。

`LOC-01`/`LOC-02`/`LOC-03` 是第 16 面补的，它们回答一个 DSH 迟早会遇到的问题：**用户说「我用本地的」，这件事要做多少工作**。答案是三档，这三条是第一、二档里最便宜的：

- `LOC-01` 的前提是一个反直觉的事实——**判对「这是本地」比判错代价大得多**。只判 `127.0.0.1` 会漏掉 WSL（172.x）、Docker Compose 服务名（无点主机名）、mDNS（`*.local`）、Tailscale（100.64/10）四种真实场景；这四种全都走云端的 120 秒 read 超时，而本地预填充要好几分钟，**请求被自己的超时掐断**。所以判定的目的不是分类，是**切一整套时序参数**。
- `LOC-02` 的依据是 Hermes 写在模块第一段的一句结论：`health-200 is NOT readiness`。本地服务器在模型还在加载、或者子进程卡在采样上时，`/health` 一样回 200。只有真让它出一次字（`max_tokens=512`、`temp-0`、**同时扫 content 和 reasoning_content**）才能证明整条解码链通了。这一条和第 15 面的「完成需要证据」是**同一条原则的两次体现**。
- `LOC-03` 是三条里唯一涉及**数据出境**的。`handed the local model slug to whatever cloud provider held a key (#119227)`——请求说「用本地」而本地没起来时，如果路由顺手挑一个云 provider，用户以为在本地跑，prompt 其实出了机器。这一条不修，前面两条做得再好也没意义。

TASK-01 虽然 L，但它是 DSH 清单里**唯一被点名"没有"的实体**，且是其它三条（工作流可恢复、任务进度、跨会话续接）的地基。建议拆成三阶段：①表 + claim ②事件流 ③完成契约与判官。

`UPD-02` 的逻辑和 `TASK-01` 相反：它不新增实体，只是把已有的迁移机制**改对一条语义**。Hermes 的 31 步迁移里，单步失败只记 warning、版本号照盖到最新，于是那一步永久不再执行（代码注释自承 "the skipped step vanishes for good"）。DSH 要抄的是阶梯，但**盖章必须停在失败点之前**。详见 `08-附录/A11`，可跑对照在 `04-参考实现/migrate-ladder.mjs`（同一份配置跑 hermes 模式与 safe 模式，stamp 分别是 51 与 44）。

`VER-03` / `VER-04` 是 M 而非 S，因为要动存储和一个新的回合出口。但两者的机制都只有一条边值得记：

- `VER-03` 的唯一关键边是 **`markEdited`**——写了代码工具成功的那一刻，之前所有证据变 `stale`。没有这条边，台账就是"曾经跑过什么"的流水账，而不是"现在能不能信"的判据。
- `VER-04` 的唯一关键动作是 **暂存而非否决**：`final_response = null` + `pending_verification_response = 原回答` + 追加一条 user-role nudge + 继续回合。这就是 Hermes `never blocks completion` 的真身——它不阻止结束，只让结束等一轮；预算耗尽时原回答还能被放出来。

⚠️ 两条共同的两个坑记在 `08-附录/A14` 的缺陷表里：**V7 跨代理盲区**（子代理改的代码不进父会话台账，`delegate_task` 型回合会绕过整套闸门）与 **V8 键空间不一致**（编辑侧用 `session_id or task_id`，查询侧只用 `session_id`）。这两个不报错，只安静放行。

`IMG-01` 是 03 面第 ⑥ 节补的，它是整份档案里**唯一一条「淘汰时机比淘汰多少更重要」**的结论：把图片按「保留最新 N 张」淘汰，每来一张新图就多淘汰一条消息，而 provider 的 prompt cache 按精确字节前缀匹配——于是每轮全前缀 miss，省下的 token 全用 cache miss 还回去。这和 `micro_summarize` 默认关（D-01）是**同一条原理的两次体现**，只是 micro 改文本、这里改消息结构。⚠️ 上线前提：先确认 DSH 真的在用 provider 的 prompt cache，否则这条收益不存在。
