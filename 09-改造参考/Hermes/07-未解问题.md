## R1 — image/video 的 enum 由 provider 运行时能力决定（静态不可得的唯一残留）

**已知**：9 个 `dynamic_schema_overrides` 钩子里，7 个的方向是**单调收窄**（运行时 ⊆ 静态字面量），照抄静态全集是安全超集。

**例外**：`image_generation` 与 `video_generation` 的 `aspect_ratio` / `resolution` / 创作控制参数，值来自 **provider 的 `capabilities()` 与 `list_models()` 调用**（`video_generation_tool.py:289-357`、`image_generation_tool.py:942-986`），**可以超出静态字面量集合**。

**缺什么才能解**：一次真实 provider 的 `capabilities` / `list_models` 响应。红线禁止运行目标程序，也不再联网，故不做。

**影响**：只影响 `image_gen` / `video_gen` 两个工具；**DSH 要抄的 15 面里没有这两个**（它们是模型能力驱动的媒体生成，与 DSH 的缺口无关）。所以这条记录在此只为把边界划清，不影响任何候选落地。

> **别把这条和 03 面 ⑥ 混为一谈**：R1 说的是**媒体生成的参数 enum**（provider 说它支持多少种宽高比），
> 而 03 面 ⑥ / `IMG-01` 说的是**图片在上下文里的驱逐**（何时淘汰历史截图才不打断 prompt cache）。
> 前者静态不可得且 DSH 不需要；后者逻辑完全在读到的代码里，且对任何多模态 Agent 独立成立。

## R2 — 长期误报率（要真实流量，不是要信息）

**已知**：
- 8 条中文模式在 **74 份真实中文文档 / 439,619 字符**上 **0 命中**（95% 上界 4.0%；叠加早前的 50 条合成样本合共 0/124，上界 2.4%）。
- 唯一的误报源是 BOM，占 16.2%，已修（`INJ-04`），修后复测 0/74。

**未知**：真实会话里的误报率。语料是"文档"，真实流量还会包含**用户贴进对话的日志、报错、别人写的 README、网页正文**——尤其"讲安全的中文博客"会成段引用攻击句式。

**缺什么才能解**：上线后采样。每次 `strict` 档拦截记录：命中的模式 id + 用户下一步动作（改措辞重试 = 误报信号；放弃 = 可能是真攻击；换说法后再成功 = 确定误报）。**至少 200 次拦截**才能把上界压到 1.5% 以内。

**暂定策略不变**：`cn_ignore_prior` 与 `cn_exfil_secret` 只放 `strict`（用户可恢复的写入路径），绝不放 `context`。**用漏检换"不污染正常读取"，是刻意选择。**

## R3 — 跨版本迁移的真实失败率（要旧样本）

**已知**：失败**形态**四条已全量读出（见 `08-附录/A11` ④），并且第一条（F1 静默跳过 + 仍然盖章）是**设计缺陷而不是偶发**——代码注释自承 "the skipped step vanishes for good"。

**未知**：某一步在真实旧配置上多久抛一次异常。`run_migrations` 的 except 把异常内容写进 warning，但 `migrate_config` 在 quiet 路径（无人值守更新）会丢弃 `results`，只剩一条 log——**线上根本无法统计**。

**缺什么才能解**：一份 v11 或 v12 时期的 `config.yaml`（`backups/` 里只有当前版本的 `config.yaml.good.<ts>`），或者一次带 `--verbose` 的跨大版本实跑。

**影响**：DSH 是全新项目，没有历史配置要迁移，**这条对 DSH 实际无影响**。记录在此是因为 F1 的修法要抄（safe 模式：失败不盖章），而失败率本身不用抄。
