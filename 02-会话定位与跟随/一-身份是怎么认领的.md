# 一 · 身份是怎么认领的

> 一个 AI 引擎同时服务好几个场景，而**引擎本身不按场景注入任何东西** ——
> 也就是说，AI 开场时对"我在哪个场景、我该干哪份活"是**空白**的。
> 所以每个场景的常驻会话，开场第一件事都是「自己认领自己」。

---

## 1. 引擎真正会自动给的，只有两样

| 自动注入 | 内容 |
|---|---|
| 全局须知（工作区里的 `AGENTS.md` 层级文件） | 全局规矩 + 一句"开场先认领身份" |
| 技能目录 | 每个技能只有 `name` + `description`（**正文要主动去读**） |

场景配置、定位卡、场景记忆**都不会**自动进上下文 —— 它们能被读到，仅仅是因为**有人告诉 AI 去哪读**。
这就是为什么"卡写了没人读"是常态，也是为什么必须有下面这四步。

---

## 2. 四步认领（开场第一件事，约 30 秒）

```
① 拿本次会话 id    引擎给每条会话的 shell 注入的环境变量（变量名随引擎而定，例：$SESSION_ID）
        ↓
② 对号            去「场景身份索引」表里找同一行 → 得到
                  场景 / 面板 / 定位卡 / 主技能 / 场景记忆
        ↓
③ 读定位卡        身份与职责 · 资产地图 · 触发词→定位 · 标准流程 · 铁律 · 上次进度
        ↓
④ 读场景记忆      §〇 当前交接（进度 / 下一步 / 卡点）+ §一 + §二
```

**四步里的关键点：**

1. **必须当场认领**：不要猜、不要信"会话记忆里的旧结论"（会话可能是从别处分叉来的，或者标题跟别人撞名）。
2. **以配置文件为准**：索引表与场景 json 不一致时，**表过期了**（json 是数据源）。
3. **一次读够，不要每轮重读**：卡与技能是开场开销，不是每轮开销 —— 每轮重读等于把上下文窗白送给它。
4. **不在表里 = 你是普通会话**：没有场景、没有卡、没有场景记忆，正常干活即可。

---

## 3. 场景身份索引表长什么样

一张表，把「会话 ↔ 场景 ↔ 面板 ↔ 定位卡 ↔ 主技能 ↔ 场景记忆」钉在一起：

| 场景 id | 面板 id | 面板标题 | 会话名（绑定字段首项） | 会话 id | 定位卡 | 主技能 |
|---|---|---|---|---|---|---|
| `<scene-a>` | `<a-ai>` | AI·A | A 场景 | `session-…` | `scenarios/a-context.md` | `<skill-a>` |
| `<scene-b>` | `<b-ai>` | AI·B | B 场景 | `session-…` | `scenarios/b-context.md` | `<skill-b>` |

两条容易搞错的：

- **一场景两条会话**（比如"底层改造 / 界面改造"）：共用一张卡，卡里分两节，靠**会话 id** 分辨自己属于哪半边；
- **表里的会话 id 会变**（换会话、分叉都会换）⇒ 换完会话要**回写这张表**，否则下次开场对不上号。

---

## 4. 认领之后：记忆写在哪（"越用越强"的唯一机制）

| 写什么 | 写去哪 |
|---|---|
| 长期有效的结论 / 决策 / 新坑 | 场景记忆的 **§五**（只追加，带日期） |
| 本次进度 / 下一步 / 卡点 | 场景记忆的 **§〇**（**覆盖更新**） |
| 项目级细节、上线记录 | 该项目自己的项目信息 |
| 新踩的坑 / 新流程 | **主技能**（技能是越用越准的地方） |
| 一行进度 | 定位卡的「上次进度」 |

> **会话可以无限换，记忆不会断** —— 因为记忆在文件里，不在会话里。
> 于是"换会话"的最后一件事永远是：**把 §〇 写好**（进度 / 下一步 / 卡点三行）。
> 细节见 [六 · 记忆分三层](六-记忆分三层.md)。

---

## 5. 身份认领失败的典型症状

| 症状 | 原因 |
|---|---|
| AI 问你"这个项目是做什么的" | 它没认领身份（没跑第 ① 步，或索引表里没有它） |
| AI 按旧结论干活、改了错的站/目录 | 信了会话记忆里的旧结论，没有当场对号 |
| 换完会话后新会话"接不上" | 旧会话**没写 §〇**，或索引表/场景 json 里的会话 id 没回写 |
| 两个场景的 AI 互相"知道"对方的活 | 共用了同一份记忆文件或同一条会话（见 [四 · 防串台](四-防串台.md)） |
