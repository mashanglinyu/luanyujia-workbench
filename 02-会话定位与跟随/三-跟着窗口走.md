# 三 · 跟着窗口走

> 上半节（[一](一-身份是怎么认领的.md) [二](二-会话绑定三字段.md)）解决"AI 知道我是谁"；
> 这一节解决"**界面把画面切到那条会话上**"—— 以及怎么确认它真的切过去了。

---

## 1. AI 面板其实就是一个内嵌网页

AI 面板（`type: "harness"`）不是自己画的聊天界面，而是一个 `<webview>`，指向 AI 引擎的 Web 界面。
由此推出三条重要事实：

1. **面板 ≈ 一个独立浏览器标签**：有自己的一套 localStorage、cookie、登录态；
2. **宿主能往里面注入 JS**（面板里是"别人的页面"，但宿主有注入权）—— 绑定会话就是靠这个；
3. **面板自己重载后注入就没了** ⇒ 宿主必须**周期性重注入**（绑定脚本因此必须幂等，见 [二](二-会话绑定三字段.md) §4）。

---

## 2. 一次"切场景"的完整时序

```
用户点场景标签
   ↓ 渲染层取该场景 json → 清空网格 → 重建每块面板
   ↓ AI 面板：按面板 id 决定自己的浏览器分区 → 建 <webview> 指向 AI 界面
   ↓ webview 加载完 → 宿主注入【布局精简 + 钉住会话】脚本
   ↓ 脚本：先"写键直达"（把 sessionId 写进本面板分区的当前会话键 → reload 一次）
          不行再"点行"（在会话列表里按标题找到那行点下去）
   ↓ 记录本次绑定成功的会话标题（键 = 面板 id + 绑定签名）
   ↓ 之后每几秒轻量重注入一次，保证"画面掉线"能被拉回来
```

**布局精简**这件事一并在这里做：内嵌的 AI 界面原本带侧栏/详情/头部，塞进一格面板里太挤，
所以注入的样式会把它们收掉、让对话区铺满 —— 这部分是纯 CSS 覆盖 + 一个常驻的纠正逻辑（对抗前端框架重渲染）。

---

## 3. "到位了没有"只能看画面

会话行 DOM 里没有会话 id，只有标题 + 状态点 + 相对时间，所以**没有任何"读回来的值"能证明画面切过去了**。可用的判据只有两个：

| 判据 | 怎么拿 |
|---|---|
| **绑定诊断小字** | 注入脚本每次都会刷新一份诊断（找没找到目标、点没点中、当前是哪条），显示在面板标题行 |
| **面板截图** | 宿主每次注入顺手截一张面板实况图**覆盖保存**，专门用来回答"眼睛看到的到底是什么" |

> 这两条的价值在于：把"我以为切过去了"变成"我能看到切过去了"。
> 面板最贵的 bug 不是崩溃，而是**静默没生效**。

---

## 4. 一个场景可以"分离"成一个独立窗口

多屏工作时，可以把某个场景丢进独立窗口（界面上通常是场景标签的右键 / 按钮）：

- 独立窗口**只有这一个场景**（URL 上带 `?solo=1&scene=<场景id>`），不受主窗口网格布局影响；
- 主窗口那边**不再重复渲染一份**，只显示一张占位卡（"这个场景正在独立窗口里显示，关掉那个窗口它就会回来"）；
- 独立窗口关掉 → 主窗口**自动把场景收回来**（不用再点一次标签）。

⚠️ **为什么不能在两边都渲染一份**：同一个场景渲染两份 = **两套定时器 + 两个 AI 界面**在同一个会话上抢操作
（用户原话："不要搞一模一样的会打架"）。同理，独立窗口里的 AI 面板要用**自己的分区**，
不能跟主窗口那条共用（见 [四 · 防串台](四-防串台.md)）。

---

## 5. 症状对照

| 症状 | 多半是 |
|---|---|
| 切场景后 AI 面板空白 / 不出内容 | 内嵌页还没加载完（重注入会兜底）；或该面板的分区是首次使用、正在初始化 |
| 画面切到别的会话去了 | 注入的脚本被页面自己的路由带跑；诊断小字会显示当前是哪条 → 看截图确认 |
| 面板每隔几秒"跳一下" | 注入脚本不幂等（装了几十个定时器）→ 修脚本，别去调注入间隔 |
| 主窗口里这块场景只剩一张卡 | 该场景正在独立窗口里跑（正常行为），关掉独立窗口即自动恢复 |
| 两个窗口对着同一条会话各干各的 | 独立窗口与主窗口共用了分区 / 会话，见 [四 · 防串台](四-防串台.md) |
