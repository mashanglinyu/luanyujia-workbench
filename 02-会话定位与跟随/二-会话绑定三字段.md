# 二 · 会话绑定三字段（★ 全仓库最核心的一页）

> 场景 json 里那三个字段 —— `sessionTitle` / `sessionId` / `pinTarget` ——
> 决定"点开这个场景时，AI 面板显示的是**哪一条**会话"。
> 三个字段**少写一个不会报错**，只会悄悄退化成"随便显示一条"或"让用户自己选"。

> ⚠️ **示例不能照抄（新手最常见的坑）**：`sessionId` 必须是**你自己引擎里真实存在**的会话 id，
> `sessionTitle` / `pinTarget` 必须是那条会话的**真实标题**。抄占位符的结果是
> **"看起来配好了、其实没钉上"** —— 而且界面上不报任何错。怎么拿到真实值：见 §3 与 §8。

---

## 1. 一句话分工

| 字段 | 一句话 | 作用方式 |
|---|---|---|
| `pinTarget` | **找谁** | 候选名列表；模糊匹配：忽略大小写与空格，**完全相等优先**，其次包含匹配 |
| `sessionTitle` | **精确是谁** | 该会话的**完整真实标题**，要求**完全相等**，优先级最高 |
| `sessionId` | **验明正身 + 直达** | 引擎真实会话 id：核对画面上的会话、写键直达、并决定**独立分区** |

---

## 2. 少了它们会怎样（这就是为什么三个都要写）

| 写了什么 | 结果 |
|---|---|
| 三个都不写 | 面板**不钉会话**：显示引擎自己记住的那条，或让用户自己点。切场景时会跟着上一条跑 |
| 只写 `pinTarget` | 靠标题找。而标题**会重名、会差一个空格、会被改名** —— 本机真的同时存在过 `XX改造` 与 `XX 改造` 两条会话，光凭标题会认错人 |
| `pinTarget` + `sessionTitle` | 基本可靠，但**"画面到底切过去了没有"仍然无从验证** |
| 再加上 `sessionId` | 才能**核对**："画面上这条，是不是我要的那条" |

---

## 3. 完整写法

```json
{
  "id": "demo-ai",
  "title": "AI·演示",
  "type": "harness",

  "sessionTitle": "演示场景",
  "sessionId": "session-00000000-0000-0000-0000-000000000000",
  "pinTarget": ["演示场景", "演示"],

  "col": 2, "row": 3, "w": 3, "h": 2
}
```

匹配顺序（同一个 `pinTarget` 数组里）：**① 标题完全相等 → ② 包含匹配**，两者都忽略大小写与空格
（所以 `日报助手`、`公司 日报助手`、`公司日报助手` 能落到同一条上）。

- `pinTarget` **按顺序**试，第一个命中的就钉住；
- `sessionTitle` 一旦给了，**完全相等是硬条件**，它对不上就继续走 `pinTarget`；
- 三个字段都指向同一条会话，才算"这条会话被认领了"。

---

### 3.1 三个字段的真实值从哪来（**别猜**）

| 要什么 | 从哪拿 |
|---|---|
| 会话**标题** | 在 AI 面板的会话列表里**原样复制**那一行（别手打：差一个空格就是另一条会话） |
| 会话 **id** | 引擎侧的会话目录名 —— 形如 `<引擎数据目录>\sessions\--<工作区转义>--\<session-xxxxxxxx-…>\`；维护了「场景身份索引表」的话那里也有一份 |
| 改完什么时候生效 | 面板**重建**时（切走再切回 / 面板自刷新）。改 json 不会当场改变已经开着的面板 |

> 一条纪律：**换完会话立刻回写这三个字段**，否则面板还指着已经归档的那条（见 [五 · 换会话与归档](五-换会话与归档.md)）。

---

## 4. 绑定是怎么发生的（四步 + 一次核对）

```
面板加载
  ↓ ① 宿主把「钉住脚本」注入 AI 面板里的对话页
       （面板里就是一个普通网页，宿主能注入 JS）
  ↓ ② 首选「写键直达」：把 sessionId 写进**本面板自己分区**的
       localStorage 里那个「当前会话」键 → reload 一次
  ↓ ③ 兜底「点行」：在会话列表里按标题找到那一行 → 点它
       （只认会话行，永不点分组头 —— 点分组头只会展开分组、不换会话）
  ↓ ④ 记下"这次钉成功的会话行的精确标题"
       （键里带面板 id + 本次绑定配置的签名）
```

两个设计细节，都值得照抄：

- **键里必须带签名**（面板 id + 当前绑定配置）。改了场景（换会话 / 删绑定）就一定要让旧记忆**立刻失效**，
  否则会出现"json 里已经删了 id，面板还按记住的标题去点旧会话"的**鬼绑定**。
- **脚本必须幂等**。宿主会周期性重注入（防止内嵌页自己重载后丢掉绑定），
  所以同一份配置只能装一次定时器 —— 否则几分钟就攒出几十个循环，表现为**"每隔一会跳一下"**、空转扫 DOM。

---

## 5. 一板一分区（★ 最容易踩的一条）

带 `sessionId` 的 AI 面板，各自用一个**独立分区** —— 命名里带上面板 id（例：`persist:ai-panel-<面板id>`；**分区名随你的壳，关键是"每板一个"**）。

| 做法 | 后果 |
|---|---|
| **一板一分区** ✅ | 各写各的"当前会话"键，互不干扰 |
| **共用分区** ❌ | 多个面板抢**同一个**键 → 用户实感「左右两个窗口都变成同一个会话」「每隔几秒跳一下刷新」 |

> 没有 `sessionId` 的面板只能退回共用分区 —— 这就是"两个 AI 面板不能都省 id"的原因。
> 分区名里**只允许字母数字下划线短横**，面板 id 别用中文和空格。

---

## 6. 判据只能是画面

**键写对了 ≠ 界面切过去了。** 会话行 DOM 里**没有会话 id**（只有标题 + 状态点 + 相对时间），所以：

- ✅ 判据一：面板标题行的**小字**（绑定诊断：找没找到、点没点中、当前是哪条）；
- ✅ 判据二：**截图**（宿主每次注入会顺手截一张面板实况图覆盖保存，用来回答"眼睛看到的到底是什么"）；
- ❌ 不要拿"我写进去的那个值"当成功证据 —— 那只能证明你写了，不能证明界面读了。

这条不只适用于会话绑定：**凡是"我改了配置 / 写了状态，指望别的层去读"的地方，都要找画面上的落点。**

---

## 7. 三条硬结论

1. **必须给会话 id，不能只靠标题认人** —— 标题会重名、会差一个空格、会被改名。
2. **判断"到位了没有"只能看画面** —— 存储值是你自己写的，画面才是结果。
3. **一个 AI 面板一个独立分区** —— 否则多面板抢同一个"当前会话"键。

---

## 8. 症状对照

| 症状 | 多半是 |
|---|---|
| 切场景后 AI 面板还是上一个场景的会话 | 三个字段都没写（不钉）；或只写了 `pinTarget` 而标题已改名 |
| 左右两个 AI 面板显示同一条会话 / 每隔几秒跳一下 | 分区共用（面板没写 `sessionId`，退回共用分区） |
| 面板一直空着、不显示任何会话 | `pinTarget` / `sessionTitle` 都对不上：按实际标题抄一遍（注意空格与大小写） |
| 改了 json 绑定却没变 | 绑定记忆按"面板 id + 绑定签名"存；改完要让面板**重建**（切走再切回 / 面板自刷新） |
| 面板标题小字显示"找不到会话" | 会话被归档/改名了 → 更新 json 里的三个字段（见 [五 · 换会话与归档](五-换会话与归档.md)） |
