# 四 · 防串台

> 多场景工作台最贵的 bug 不是崩溃，而是**串台**：两块面板显示同一条会话、两个窗口抢同一份状态、
> 一个场景的数据落进了另一个场景的口袋。这一节讲隔离是怎么做的。

---

## 1. 隔离的四个层次

| 层次 | 隔离手段 | 不隔离会怎样 |
|---|---|---|
| **界面** | 一个场景 = 一份 json + 一块网格 | 改一个场景动到所有人 |
| **会话** | 每个 AI 面板绑自己的会话（[二](二-会话绑定三字段.md)） | 两个面板显示同一条会话、互相顶掉 |
| **存储** | **一板一分区** + 存储键带面板 id / 场景 id | 抢同一个"当前状态"键 → 每隔几秒跳一下 |
| **数据** | 面板 `meta.scenario` 前缀；每个场景自己的记忆文件 | A 场景的数据被 B 场景读写 |

一条经验：**凡是"全局唯一"的东西，都不许被两个面板共用** —— 要么各自一份，要么显式串行化（见 §3 的抢单）。

---

## 2. 一板一分区：把"当前会话"键隔开

浏览器层面，每个 `<webview>` 可以指定自己的**分区**（partition）。带会话 id 的 AI 面板一律用
**"这个面板专属"**的分区（命名随你的壳，例：`persist:ai-panel-<面板id>`）：

- 每个面板写自己的 `当前会话` 键 → **各写各的，不会互抢**；
- 分区是 `persist:` 前缀 ⇒ 登录态与记忆持久化，重启程序还在；
- 面板 id 里**只用字母数字下划线短横**（分区名有字符限制）。

**历史上的坑**：早期所有 AI 面板共用同一个分区，而"当前会话"只有一个键 ⇒ 多面板同开时互相覆盖，
表现是"左右两个窗口都变成同一个会话""每隔 8 秒对刷一次"。
改成"一板一分区"后彻底消失。**别改回共用。**

---

## 3. 多个窗口 = 多套壳：抢单必须认身份

一个场景被分离成独立窗口后，**每个窗口都是一整套完整的壳**（自带的预加载 + 渲染层 + 各脚本）。
如果这些壳里都有"接收任务"的能力，就会出现**两份实现抢同一个任务**。

对策是**抢单 + 核对发起方**：

```
任务发出时记下"应该由哪个窗口处理"
   ↓ 各窗口都收到任务 → 谁想处理先"认领"
   ↓ 宿主核对发起方 id：不是目标窗口的认领 → 直接丢弃
   ↓ 交卷时再核对一次：不是目标窗口交的卷 → 结果作废
```

这样"旧窗口按老逻辑抢答"这类问题就变成**可检测、可丢弃**，而不是"偶发拿到别的窗口的答案"。
配套的还有**版本申报**：每个窗口启动时申报自己那份脚本的版本，版本不一致时宿主直接提示"这个窗口的脚本是旧的，重启一次"。

> 一句话：**跨窗口的协作，不能靠"约定"，要靠"核对身份"。**

---

## 4. 数据分区：存储键带前缀

面板复用在多个场景里是常态（一个文件面板可能出现在三个场景里），所以：

```js
const key = 'my-panel:' + meta.scenario + ':' + meta.id;   // ✅
const key = 'my-panel';                                     // ❌ 三个场景互相覆盖
```

同理，**AI 面板"记住的上次绑定会话"也要按面板分键**，否则换场景后会出现"按旧记忆去点旧会话"的鬼绑定。

---

## 5. 隔离不等于复制：该共享的要想清楚

不是所有东西都该隔离。判断标准是**"这算不算同一份事实"**：

| 该共享 ✅ | 该隔离 ❌ |
|---|---|
| 全局须知 / 全局偏好 | 每个场景的会话与绑定 |
| 同一个账号的登录态（同一分区） | 每个面板的"当前会话"指针 |
| 公共素材、公共脚本 | 每个场景的存储键与数据 |

> 反例：曾经为了"登录态联通"让两个面板共用分区，结果把"当前会话"也一起共享了 ⇒ 互抢。
> 正确做法是**只共享该共享的那一层**（登录态），键仍然各写各的。
