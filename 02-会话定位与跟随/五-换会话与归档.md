# 五 · 换会话与归档

> 一个常驻会话迟早会到上下文上限。**"换会话"这件事必须是一条命令**，而不是一套让用户背下来的手工流程 ——
> 因为只要有一处没做（旧会话没真归档、配置没回写），下次开场就会对不上号。

---

## 1. 先分清：什么时候**该**换，什么时候不该

| 情形 | 该不该换 |
|---|---|
| 看到上下文压力到线（工具报的百分比、⚠ 之类） | ❌ **不该**。到线会自动压缩，任务可以继续做完 |
| 压缩之后**仍然**报"上下文超限 / 413 之类的硬错误" | ✅ 该换（真死锁了） |
| 用户明确说"换会话 / 归档并新建" | ✅ 该换（用户说了算） |
| 只是"觉得会话有点长了" | ❌ 别换 —— 中途换会话 = 把没干完的活扔给下一条会话 |

> 判据只认**当场跑出来的那一行**压力输出；交接文档/摘要里的历史数字只属于写它的那条会话，不能拿来判断现在。

---

## 2. 换会话的标准四步（脚本全包了）

**第 0 步永远是：把交接写好。** 场景记忆里那三行 —— 进度 / 下一步 / 卡点。
记忆在文件里，不在会话里；**没有交接的换会话 = 记忆断档**。

```
① 建新会话     同名新建（会话名 = 场景的绑定名，别改名，否则回写后又对不上）
② 旧会话归档   改名成「已归档 · …」+ **真归档**（只改名不算归档，还会留在侧边栏里）
③ 新会话开场   自动写入一条开场消息："先读 §〇 交接，再干活"
④ 回写 + 自检  把新会话 id 写回场景 json（sessionId / sessionTitle）→ 跑一次同步点自检
```

入口脚本提供"傻瓜包装"，一般只需要记一条命令：

```bash
node scripts/换会话.mjs <面板id>          # 空跑：打印计划、交接文件与新旧程度，不动任何东西
node scripts/换会话.mjs <面板id> --go     # 真换：上面四步全做
```

它替你处理的三件麻烦事：

1. **自己找到交接文件**（面板 id → 场景记忆的映射表写在脚本里）；
2. **交接太旧就不硬来**：超过"新鲜窗口"（例如 2 小时）会拒绝执行并提示"要么去写 §〇，要么加 `--force`"；
3. **干完透出完整报告**（含轮换后的自检结果）—— 不用你再去核对一遍。

---

## 3. 为什么必须自动化（手工会漏的三处）

| 手工做法 | 漏在哪 |
|---|---|
| 新建一条会话，把旧会话**改名** | 改名 ≠ 归档：旧会话还挂在侧边栏，用户下次还会点进去，然后在一个"死"会话里接着聊 |
| 不回写场景配置 | 面板还按旧 id / 旧标题找会话 → 显示"找不到会话"，或者钉到已归档的那条上 |
| 不给新会话写开场消息 | 新会话开场是空白的，用户得自己说"你去看 §〇" —— 而它并不知道 §〇 是什么 |

> 附带一条：**空会话不进侧边栏**。所以"建完还没说话"的会话看起来像没建成 —— 这是正常的，别重复建。

---

## 4. 另一条路：分叉，而不是新建

如果只是"这一段太长，但前半段的成果还想留着"，可以从**较早的一条消息**上分叉：
分叉只带走分叉点之前的历史 —— 相当于"把前半段搬进新会话"。

- 分叉完同样是**回写配置 + 自检**这两步（新会话是新的 id）；
- 适合"任务做了一半、上下文太满"的场景；纯粹换脑则用 §2 的轮换。

---

## 5. 零散会话（没有场景面板的那些）

不在场景表里的会话没有"面板 id"可填，但它们同样需要交接。做法是：
**一份临时交接文档 + 同一条命令**（加个 `--stray` 标志，用会话名而不是面板 id），
真换同样是四步全做，并顺手把交接文档里的旧会话 id 换成新的。

> 结论：**"换会话"是一个可重复的、有自检的原子操作**，不管这条会话有没有场景。

---

## 6. 换完要做的三件事（别漏）

1. 场景 json 里的 `sessionId` / `sessionTitle` 已回写（脚本做了，但**值得看一眼报告**）；
2. 身份索引表里的会话 id 同步（如果维护了这张表）；
3. 在界面上让那个面板**重新加载**一次 —— 它会按新的三字段重新钉会话（见 [二](二-会话绑定三字段.md) §8）。
