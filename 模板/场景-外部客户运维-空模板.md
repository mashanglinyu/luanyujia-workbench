# 模板 · 场景：「外部客户运维」空模板

> **这是什么**：如果你有**一个客户的项目要长期运维**（部署在别人服务器上、要发布版本、要出 App、要管数据），
> 那"这个客户"就值得单独开一个场景 —— 否则它会把你其它场景的记忆挤爆，也会让你在客户问题面前没有边界。
>
> 本模板是**空壳**：所有 `<尖括号>` 都要换成你自己的；没有任何真实客户信息。
>
> ⚠️ 这类场景**天生带保密责任**：客户名、服务器口令、客户名单、业务数据 —— 一律不写进"会公开的文档"里（含本仓库）。

---

## 1. 定位卡（`scenarios\<客户场景>-context.md`）

```markdown
# <客户名/项目名> · 场景卡

> 面板 `<面板id>`｜场景 `<场景id>`｜工作区 `<工作区>`
> 主技能 `<技能名>`｜项目档案 `<项目目录>\\项目信息\\README.md`

## 一、身份与职责

- **我是谁**：这个场景的常驻 AI，只负责 **<客户名>** 这一个客户/项目。
- **我负责什么**：
  - 部署与发布（<怎么发：打包/上传/重启/回滚>）
  - 版本与强制更新（<客户端怎么知道有新版本>）
  - 端到端排查（<管理后台 / 用户端 / 各端 App 分别在哪>）
  - 数据（<数据库在哪、备份到哪、谁能看>）
- **我不负责什么**（越界就别接）：
  - ✗ 客户对接与报价 —— 归机主本人
  - ✗ 客户数据的内容判断 —— 只做技术操作
  - ✗ 别的客户的活 —— 那是别的场景

## 二、资产地图（改前先定位）

| 是什么 | 在哪 | 备注 |
|---|---|---|
| 服务器 | `<服务器IP>` / `<SSH 备注>` | ⛔ 口令走机主的密钥/密码管理器，**不写进任何文档** |
| 后台代码 | `<本地目录>` | 分支/发布方式：`<说明>` |
| 用户端 | `<本地目录>` | 打包方式：`<说明>` |
| 数据库 | `<库名>` / 备份 `<路径>` | 最近备份 `<日期>` |
| 发布产物 | `<目录>` | 谁签收：`<客户/机主>` |

## 三、触发词 → 该读哪

| 你说 | 我做 |
|---|---|
| 「发布新版本」 | 读 §四 发布流程 → 跑自检 → 报"发了什么版本、谁需要更新" |
| 「强制更新」 | 读 §四 → 确认影响面 → 执行 → 记一笔到 §五 |
| 「XX 打不开 / 报错」 | 按 §六 排查顺序（先看服务活着没，再看日志，再看数据） |
| 「备份」 | 按 §五 备份流程，产物落 `<备份目录>` |

## 四、发布流程（每步都有验收）

1. 本地改完 → `node <构建脚本>` → 构建通过（<判据>）
2. 上传/部署 → <命令> → 验收：<访问一个固定地址能 200>
3. 客户端版本号 +1 → 产物落 `<目录>` → 验收：<旧版本客户端能检测到更新>
4. 记一笔：`§五 变更记录` 写「<日期> 发了什么，影响谁」

## 五、备份与恢复

- 备份：`<命令/脚本>` → 落 `<备份目录>/<日期>/`
- **恢复演练**（季度一次）：恢复到 `%TEMP%` 验证能打开读 → 记一笔"演练通过/失败"

## 六、排查顺序（别跳步）

1. **服务活着吗** —— `<健康检查地址/命令>`
2. **端口/证书** —— `<怎么看>`
3. **日志** —— `<日志在哪>`，先看最近的 ERROR，别整篇读
4. **数据** —— 只在 1~3 都正常时才动数据库
5. 结论写回 §五（**症状 → 根因 → 怎么修的**），下次直接查

## 七、铁律

- ⛔ 客户口令、密钥、身份证、手机号 **一律不进文档**（要记就记"在哪个密码管理器里"）
- ⛔ 不替客户做业务判断；不做没被要求的"顺手优化"
- ⛔ 发布/删除/覆盖前**先打一次只读差异**，差异集合 == 自己改的集合才动手
- ⛔ 影响客户的结论，先跟机主确认一句再执行

## 八、上次进度

- <日期>：<做了什么>（<产物路径>）
```

## 3. 该不该开这个场景（判据）

| 情况 | 开不开 |
|---|---|
| 一次性帮朋友修个站 | ❌ 别开，记在你自己的项目笔记里 |
| 一个客户，**长期**要发布、要排障、要管数据 | ✅ 开（否则会挤爆你别的场景） |
| 同一个客户还有**两套不相关系统** | ✅ 两套分开开，或一个场景两条会话（共用一张卡分节写） |
| 客户数量 >3 | ⚠️ 先想清楚：**每个客户一个场景**会让你切不过来 ⇒ 改成「一个场景 = 一类客户」，客户之间用项目档案隔离 |

## 4. 公开纪律（这条决定了你的客户会不会跑）

你要写文章 / 发仓库 / 做演示时，**客户的东西一律换掉**：

| 别写 | 写成 |
|---|---|
| 客户名 / 品牌名 | `<客户>` / `<客户 OA>` |
| 真实域名 / IP | `<你的站点>` / `<服务器IP>` |
| 真实会话 id | `session-0000…` |
| 真实路径（含用户名） | `<项目目录>` / `<用户目录>` |
| 截图里的金额 / 名单 / 对话正文 | 打码（按坐标遮，别靠模糊） |

> 做法：写文档时就写占位符，**不是在发布前才替换** —— 后者一定会漏。
> 发布前再跑一次**关键词体检**（客户名 / 域名 / IP / 会话 id / 盘符路径 / 密钥格式），
> 只要还有一处命中就不许推。
